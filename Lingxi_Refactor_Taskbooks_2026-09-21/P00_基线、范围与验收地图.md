# P00任务书｜基线、范围与验收地图

版本：1.0｜日期：2026-09-21｜研究仓库：`ItsDalk-Lane/LingxiAgent`｜研究基线：`8037fae7a6f621549f5b7db4c4d0bba3862ddc07`。

**状态：待执行计划。不是代码交付或测试通过报告。** 本阶段与[01_通用执行约束.md](01_通用执行约束.md)共同使用；只执行本阶段，前后阶段通过交接文件传递证据。

## 1. 本阶段目标

在不修改生产业务行为的前提下，确定本轮究竟保护哪些功能、修哪些边界、怎样证明完成。产出后续八阶段可直接使用的事实和测试地图，而不是一份只有目录的调研报告。

## 2. 前置输入与进入条件

无前置阶段。仅需取得有权限的本地仓库。执行前先读取实际存在的 AGENTS.md、CONTRIBUTING.md、tests/README.md 和各目录约束；不存在的文件记录缺失，不自行编造。

进入后先比对实际代码；已正确实现采用UNCHANGED_VERIFIED，不强行重写。前置阻塞不能伪装通过。

## 3. 范围和明确不做的事

**本阶段允许范围：** 仓库与工作区清点、可达调用链、功能与数据契约、既有测试基线、隔离测试夹具、初始性能与提示词预算测量、后续改动清单。允许新增测试基础设施和文档；不得以摸底为名改生产分支逻辑。

**明确不做：** 不升级依赖、不切换技术栈、不移动大批文件、不先行修改权限/提示词/消息规则、不运行真实有副作用任务、不修改发布版本和历史审计结果。

## 5. 逐项执行任务

每项依次完成“读实际实现→建立/复用失败或保护场景→最小改动→运行证据→删除本项不再需要的旧路径”。每项输出名称是交付建议；已有同职责报告可扩展，但必须保留任务ID映射。

### P00-T01｜固定代码、环境和授权边界

**要做什么：** 让所有后续结论指向真实可重现的输入。

**输入：** 本阶段前置交接、上表对应实际源码、此前任务产出以及P00验收地图。缺少输入先记录，不猜造。

**怎么做：**

1. 记录 git status --short、当前分支、HEAD、锁文件摘要、node/npm 版本、操作系统与架构；对比本任务书研究基线，不强制 reset 到旧提交。保存用户已有未提交修改的文件清单，禁止覆盖。

2. 检查当前 AGENTS/贡献规则、完整历史与 tag 可用性、node_modules 与锁文件是否匹配。安装依赖只能在允许的工作区按现有脚本执行；日志不得打印密钥。

3. 为重构建立独立工作分支或经授权的现有分支，记录其起点。仅有任务书不等于允许 push、开 PR、创建 tag 或发布；写入范围是本地当前阶段。

4. 创建隔离测试 HOME/工作区/端口，确认启动器是否覆盖 LINGXI_HOME；在启动前和启动后均断言实际路径不等于真实用户目录。无法隔离的命令禁止运行。

**必须交付：** BASELINE.json、WORKTREE_SAFETY.md、隔离路径证明。

**任务完成检查：** 工作树原有改动未丢失；运行环境来自实测；真实数据目录零读写（除明确授权的只读样本）。

### P00-T02｜把产品范围变成可核对的清单

**要做什么：** 把当前采纳功能和已撤回方案彻底分开。

**输入：** 本阶段前置交接、上表对应实际源码、此前任务产出以及P00验收地图。缺少输入先记录，不猜造。

**怎么做：**

1. 从 README、路由注册、工具注册、设置入口、后台注册及构建入口交叉列出功能，不按目录名猜测。按已采纳/外装扩展/已撤回/仓库残留/待确认分类。

2. 至少覆盖聊天与会话、四基础工具及按需发现、审批沙盒、当前子代理功能、人格与 MOOD、记忆、当前知识库、资源与交付文件、模型与媒体配置、浏览器/终端/桌面系统能力、已存在 Bridge/Web/CLI、后台任务、用量观测、导入导出和更新。

3. 每项记录用户动作、入口、可观察结果、数据所有者、现有测试、归属阶段。不得把外装 MCP 数量和电脑私有插件当作内置功能；用合成适配器覆盖扩展边界。

4. 写入硬排除：不恢复专用子代理目录/强制派发重构，不恢复独立知识研究与已撤回本地模型子系统，不新增产品能力、不改变现有 UI 布局。发现残留只登记，未经判定不得删掉仍有迁移用途的代码。

**必须交付：** FEATURE_MATRIX.md、SCOPE.json、排除项登记。

**任务完成检查：** 每个已采纳功能都有归属；“源码存在”与“用户仍要求保留”没有混为一谈。

### P00-T03｜绘制真实调用链与事实所有者

**要做什么：** 为“只有一个权威来源”建立可检查的对象。

**输入：** 本阶段前置交接、上表对应实际源码、此前任务产出以及P00验收地图。缺少输入先记录，不猜造。

**怎么做：**

1. 逐一追踪桌面用户输入、CLI、已存在远程/Bridge 输入、定时任务、子任务到实际模型/工具调用的路径，记录文件、符号、分支条件及真实调用点。

2. 分别登记 session、用户 turn、业务 task、单次 run/attempt、model call/attempt、tool call、trace、resource 的身份产生位置与写入者；不要预设同名概念必然相同。

3. 单独记录当前会话级用户 trace 复用、后台新 trace 和未知因果=null 的规则；TaskRegistry 不是默认的前台运行总管。

4. 给每种事实列出现有权威、只读消费者、派生缓存、允许例外及检测方式。已有正确边界标记“复用验证”；仅将可复现缺口写成缺陷，未验证写“风险待验证”。

**必须交付：** ENTRYPOINT_MATRIX.md、OWNERSHIP_MAP.md、CALLSITE_MATRIX.json。

**任务完成检查：** 所有入口能追到真实执行；没有用“应该经过网关”代替调用证据；无重复注册新总管。

### P00-T04｜建立行为规格与回归样本

**要做什么：** 让旧行为可比较，同时不把旧错误固定下来。

**输入：** 本阶段前置交接、上表对应实际源码、此前任务产出以及P00验收地图。缺少输入先记录，不猜造。

**怎么做：**

1. 按本包验收场景库映射已有测试，优先引用真实生产路由/服务/store。查明当前测试只证明单元、接线还是安装包，不用一类证明替另一类。

2. 对确认缺陷先建立失败场景或可重现脚本，记录基线期望失败；保持其独立运行，不使用 skip/todo 假装通过。后续归属阶段修复后并入正常 CI。

3. 制作无私人内容的固定夹具：多轮调用/工具分片/拒绝审批/空输出/部分失败/旧历史/重复分页/文件引用/跨会话。替换 provider、时钟、网络等外部边界，不替换被测业务链本身。

4. 建立需求ID→场景ID→测试路径与用例名称→调用生产入口→证据文件的关系。一个高层场景可对应多个具体测试；不可用文件数量替代覆盖。

**必须交付：** ACCEPTANCE_MAP.json、fixture 清单与摘要、已知失败复现。

**任务完成检查：** 每项关键要求可自动检查或有明确手工步骤；旧缺陷与保留契约有区别。

### P00-T05｜运行一次可信的基线检查

**要做什么：** 确定本轮新增失败，而不是重抄提交说明里的测试数字。

**输入：** 本阶段前置交接、上表对应实际源码、此前任务产出以及P00验收地图。缺少输入先记录，不猜造。

**怎么做：**

1. 按仓库要求准备环境后运行 typecheck、lint、renderer build、npm test 和现有工具边界检查。不得因一次命令失败而继续报总体通过；逐条保存 exit code。

2. 将失败分成生产缺陷、测试缺陷、环境缺失、偶发基础设施；必要重跑须保留第一次失败，不可仅保留最终绿。没有变动无需重复全部命令。

3. 检查四组平台/架构 CI 和 open server/Windows standalone 边界的实际可用证据，记录其 SHA。旧提交的绿色结果只能当旧证据，不能证明未来提交。

4. 确认本阶段不用修复无关预存缺陷；涉及数据损坏、越权或会阻断后续基线的事项列阻塞。非阻塞旧问题登记归属和复现条件。

**必须交付：** BASELINE_TESTS.json、原始日志、BASELINE_FAILURES.md。

**任务完成检查：** 没有把未运行记成通过；每个失败可归类和复现；测试范围没有被减少。

### P00-T06｜冻结可重复的性能与上下文测量方法

**要做什么：** 先定义测什么，再讨论优化收益。

**输入：** 本阶段前置交接、上表对应实际源码、此前任务产出以及P00验收地图。缺少输入先记录，不猜造。

**怎么做：**

1. 为启动、长历史分页、持续流式输出、取消响应、空闲与峰值内存建立小/中/大三个固定工作负载；具体数量与机器条件写入基线，不复制生产会话。

2. 区分本地编排基准与真实网络端到端测量；固定模型替身、随机种子、输入、并发、缓存冷暖条件，记录整个进程树资源与后台工作量。

3. 连续指标预热后每工作负载至少30次，启动至少10次；报告样本、median、p95、范围。启动10次的高分位稳定性有限，不能作严格尾延迟证明。不能达到次数时标实验受限。

4. 在同一模型配置和上下文 fixture 下捕获最终请求，分别计平台规则、能力目录、工具schema、任务资料和用户内容的 token/字节。无对应 tokenizer 时明确字节代理，不能称精确 token。

5. 生成预先承诺的比较规则：关键正确性零容忍；性能默认以同环境基线及重复试验的波动区间比较，稳定出现超过10%劣化即阻塞；有既定产品SLO时同时满足。该10%是本计划建议阈值，不是现有性能事实。

**必须交付：** BENCHMARK_PROTOCOL.md、baseline 原始样本、PROMPT_BASELINE.json。

**任务完成检查：** 优化前后的工作负载可重放；没有关闭功能、少读数据或减少工具说明来伪造收益。

3. 每个缺陷只有一个主责阶段，跨阶段只引用依赖；不允许九份任务书各修一次同一个网关。

## 6. 必须覆盖的验收场景

下表是必须实现/映射的场景规格，不是已经运行的测试。实际测试名、命令、生产入口、证据路径在ACCEPTANCE_MAP.json登记。安全关键场景需展开全部实际可达路径；N/A必须证明不可达。

| 场景ID | 场景 | 准备 | 操作 | 必须观察到的结果 |
|---|---|---|---|---|
| P00-A01 | 工作区保护 | 存在用户未提交修改和一个未跟踪文件 | 执行全部P00清点及样本生成 | 用户文件内容与状态不变；新文件均落在批准路径。 |
| P00-A02 | 基线漂移 | 本地HEAD与研究SHA不同 | 生成源差异和受影响阶段列表 | 不reset；未核对项目标待复核，不沿旧行号盲改。 |
| P00-A03 | 真实数据隔离 | 真实HOME路径为只读哨兵，启动器可能改LINGXI_HOME | 启动测试server并写一条合成记录 | 实际写入只到隔离目录；路径不明则拒绝启动。 |
| P00-A04 | 功能排除 | 范围内混有旧专用子代理和已撤回本地模型词条 | 审查功能表 | 它们不进入实现任务；仍有旧数据兼容用途则只登记。 |
| P00-A05 | 失败诚实 | 构造一个必失败测试及一个环境缺失命令 | 运行日志收集 | 分别显示FAIL/BLOCKED，exit code保留，不能汇总为PASS。 |
| P00-A06 | 证据关联 | 一个任务标记完成但无测试命令或生产入口 | 运行交付清单检查 | 阻止该项通过，并指出缺失字段。 |
| P00-A07 | 轨迹口径 | 用户会话两轮、一个后台触发 | 记录基线行为 | user_turn按既有会话规则复用，后台独立根；不得把traceId当sessionId。 |
| P00-A08 | 性能可比较 | 相同输入运行两批；另有少处理数据的假优化 | 比较数据与样本摘要 | 相同输入可比较；输出/任务量不等价的报告无效。 |
| P00-A09 | 脱敏样本 | 输入含合成密钥和用户内容标记 | 导出通用报告、fixture、日志 | 日志/索引无敏感标记；获批原始payload单独受限，不公开。 |
| P00-A10 | 阶段边界 | 基线发现无关UI优化和一项安全阻塞 | 分类并生成后续事项 | UI建议不加入当前阶段；安全阻塞明确不隐瞒。 |

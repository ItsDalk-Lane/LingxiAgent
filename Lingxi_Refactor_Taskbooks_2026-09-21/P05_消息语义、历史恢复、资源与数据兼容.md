## 1. 本阶段目标

把已有规范化消息、流缓存、历史分页和资源引用真正接成同一语义链；让实时、重连、重新进入和导出显示一致，且旧数据不会因内部重构丢失。

## 2. 前置输入与进入条件

P04 PASS；具备P02的运行结局和P04的规范化模型事件；P00已冻结旧历史、分页和资源契约。

进入后先比对实际代码；已正确实现采用UNCHANGED_VERIFIED，不强行重写。前置阻塞不能伪装通过。

## 3. 范围和明确不做的事

**本阶段允许范围：** 现有assistant event normalizer、session stream store、WS消费、history builder/chat store、历史读取与索引、Resource/SessionFile、旧格式读取及数据指纹。

**明确不做：** 不新增全量事件溯源平台、不替换所有数据库/JSONL、不用全量加载代替分页、不以新global seq重建现有streamId/seq、不重写UI布局、不删除仍受支持的旧历史读取。

### P05-T01｜确认内容类型与结果裁决的现有权威

**要做什么：** 不要让服务器、前端和历史各猜一次。

**输入：** 本阶段前置交接、上表对应实际源码、此前任务产出以及P00验收地图。缺少输入先记录，不猜造。

**怎么做：**

1. 追踪供应商输出→normalizer→WS→前端blocks→持久历史→history builder的实际映射，列出text/reasoning/commentary/final、MOOD、tool、file、控制卡、status的语义来源。

2. 区分原始供应商内容、规范化内容、UI派生块；正常对话文本里出现类似标签时不得无差别删除。旧标签兼容仅在有明确协议/来源的适配边界执行。

3. 将P02的执行终态与现有交付结局映射连接，不以文本长度、工具数量、某一页是否有答案等启发式重新裁决整轮。

4. 将现有unresolved/晚到phase的规则记录为明确适配策略，不能一律提前当final或无限缓冲。变更语义需列差异及批准依据。

**必须交付：** MESSAGE_SEMANTICS.md、生产者/消费者映射和语义fixtures。

**任务完成检查：** 每类内容可追到事实来源；没有新增第三套正文解析器。

### P05-T02｜收口规范化事件并规划旧输出退出

**要做什么：** 已有canonical输出不是迁移已经完成的证明。

**输入：** 本阶段前置交接、上表对应实际源码、此前任务产出以及P00验收地图。缺少输入先记录，不猜造。

**怎么做：**

1. 逐个定位canonicalEvents与visibleTextDeltas等旧输出的消费者，标明真实桌面、旧客户端、导出和后台接收能力；不要只搜索生产者。

2. 将本轮可迁消费者改为同一规范化契约，保留必要协议适配但只转换不再裁决语义。进程间事件带已有stream/call/segment身份。

3. 每迁一组消费者，做双投影只读对照；不双执行、不双写真实数据。对照只规范化时间和随机ID等明确噪音，正文、文件身份和结局不裁掉。

4. 旧输出仅在所有受支持消费者有新路径或明确兼容adapter时删除。未升级远程客户端的兼容属于产品契约，不是可随意删的冗余。

**必须交付：** CONSUMER_MIGRATION.md、只读对照和旧输出退出证据。

**任务完成检查：** 每个消费者实际收到一次内容；没有同时订阅新旧流导致双倍消息。

### P05-T03｜复用streamId/seq实现可解释重连

**要做什么：** 有界缓存丢了片段时不得假装完整。

**输入：** 本阶段前置交接、上表对应实际源码、此前任务产出以及P00验收地图。缺少输入先记录，不猜造。

**怎么做：**

1. 保留S25已有每轮streamId/seq和数量/字节上限，检查序号仅在对应stream内比较。不同stream的seq=1不能去重成同一事件。

2. 重复事件幂等；旧stream事件不污染新stream；缺口、reset、truncated走已有重建/历史补取通道。缓存截断或大事件压缩必须可观察，不能把缺字段当原始完整结果。

3. 在订阅与历史快照切换期间设计有明确水位的接合，先记录协议现状再作最小补充；同一事件不能既由补取追加又由实时追加两次。

4. 流结束后缓存清空，恢复使用已持久历史和终态，而不是依赖已消失ring buffer。必要新增最小协议字段要有版本和旧客户端路径，不更换全部传输。

**必须交付：** RECONNECT_CONTRACT.md、真实WS恢复测试。

**任务完成检查：** 重复、乱序、截断、跨stream均不丢/重用户交付；未知完整性不报完整。

### P05-T04｜保护跨页Run归并和有界读取

**要做什么：** 不让页面片段决定全局结局。

**输入：** 本阶段前置交接、上表对应实际源码、此前任务产出以及P00验收地图。缺少输入先记录，不猜造。

**怎么做：**

1. 复用server/history-read与现有sessions路由/历史投影，按P00定位现有目录缓存、字节窗口和增量机制；已正确实现只回归，不再重做优化。

2. 明确分页游标是读取位置而非UI展示ID，过滤掉整页时仍能推进。相邻Run不误并，同Run跨页不拆出多次无最终回复。

3. 验证活跃末尾、重复页、乱序页、分支/重试、隐藏输入、附件跨页及索引失效后的行为。损坏索引可重建，但不能修改原始会话掩盖坏数据。

4. 对大历史测量实际读取字节和投影次数；固定page size时不得退化成每页全读全parse。必要首建索引成本单独统计，不能与后续分页混算。

**必须交付：** HISTORY_PARITY.md、分页/读取计数回归。

**任务完成检查：** P00相同长会话分页输出逐块等价；不通过all=1生产全量加载逃避跨页问题。

### P05-T05｜统一历史资源身份与安全预览

**要做什么：** 保证过去的交付不会被现在的文件替代。

**输入：** 本阶段前置交接、上表对应实际源码、此前任务产出以及P00验收地图。缺少输入先记录，不猜造。

**怎么做：**

1. 复用Resource/SessionFile/现有大结果sidecar定义，区分历史不可变内容引用、工作区当前文件、预览和全文。需要快照的结果沿现有登记机制完成。

2. 查看详情/下载/导出均重新校验当前请求主体的资源访问权限，但不重新执行当时工具；权限变化不把受限全文放进摘要。

3. 多内容块逐块脱敏和保留结构，不能只过滤第一块或用首段判断整个结果安全。secret标记只用合成数据测试。

4. 文件移动、已删除资源、过期令牌、旧别名和当前同名文件分别有明确行为；不可访问明确返回原因，不假装空文件。

5. 文档/PDF、媒体等专业生成链保持现有实现，仅调整登记、引用与展示接线。

**必须交付：** RESOURCE_HISTORY_CONTRACT.md、完整块/全文授权/历史下载测试。

**任务完成检查：** 预览不是全文唯一副本；历史全文不会被当前同名文件或重新生成结果替换。

### P05-T06｜处理必要的数据格式变更与回退

**要做什么：** 代码能回退不代表数据可以直接倒退。

**输入：** 本阶段前置交接、上表对应实际源码、此前任务产出以及P00验收地图。缺少输入先记录，不猜造。

**怎么做：**

1. 列出现有数据类别与版本，只修改本阶段必需字段；没有必要则明确“无schema变更”，不要创建迁移以显示工作量。

2. 若变更，按现有data epoch、migration、fingerprint机制实施；先复制数据并验证一致备份/敏感文件权限，原数据保留。SQLite WAL数据库用一致性备份路径，不能在线只复制主文件。

3. 新读兼容旧记录，迁移幂等、可中断重入，失败不激活半套数据。索引等派生数据可重建，原始消息/资源/凭证不能丢弃。

4. 标明可回退代码与数据版本组合；有新增用户记录后不能直接恢复旧快照。必要时隔离新数据只读，导出/转换或前向修复，禁止直接覆盖。

5. 源变更引发指纹变化时，说明语义是否变化，运行仓库现有生成与验证脚本后更新新指纹；不手改历史封印或关闭tripwire。

**必须交付：** DATA_COMPATIBILITY.md、迁移/无迁移证明、备份恢复演练与指纹diff。

**任务完成检查：** 旧数据可读且原件不变；中断不半迁移；回退不会丢切换后的记录。

### P05-T07｜完成从真实路由到真实store的等价测试

**输入：** 本阶段前置交接、上表对应实际源码、此前任务产出以及P00验收地图。缺少输入先记录，不猜造。

**怎么做：**

3. 补旧客户端兼容、资源越权、大结果截断、磁盘失败、索引损坏测试；生产函数不能全部mock掉。

4. 加入故障注入：让一个来源错误地把commentary当final、让分页游标使用展示ID，确认现有/新增测试真的失败。

**必须交付：** LIVE_HISTORY_REPLAY_REPORT.md、用户动作链测试和负向证明。

**任务完成检查：** 能够捕获历史上“退出后恢复正常”的同类不一致，而不是只测两份相同fixture。

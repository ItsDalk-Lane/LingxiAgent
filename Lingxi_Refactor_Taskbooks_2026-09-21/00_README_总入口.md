本包包含九份独立阶段任务书、68项执行任务、124项验收场景规格，以及通用约束、源码依据、执行提示词和证据模板。所有实施/验收状态均为NOT_STARTED。本包不是代码补丁，也不包含虚构的测试结果。

## 1. 怎样使用

先阅读[01_通用执行约束.md](01_通用执行约束.md)，再将本目录交给编码模型，使用[91_执行提示词.md](91_执行提示词.md)中的P00提示词开始。每次只执行一阶段；完成报告并验收后，由用户明确指定下一阶段。

不要将九个阶段当成一次不限范围的全仓修改授权。后续阶段文件已经写全，但必须使用上一阶段的真实交接和最新源码定位，不能照旧行号机械修改。

## 3. 本轮特别保护的既有设计

现有工具网关与边界检查继续使用（S06/S08）；现有Pi适配和规范化消息继续使用（S05/S10）；现有streamId/seq与有界缓存不重做（S25）；用户会话多轮观测复用规则保持（S11）；当前前后端与浏览器/PDF能力保留（S04/S19/S20）。固定提交依据见[90_源码依据与参考资料.md](90_源码依据与参考资料.md)。

这些是已经存在的实现起点，不是全部路径已完成的结论。对已有正确项只复核；有真实缺口才改。重点是把已建立边界接通、验证并完成重复路径退出。

## 4. 顺序与并行约束

```text
P00 基线
  → P01 边界/类型
  → P02 生命周期
  → P03 工具
  → P04 模型/凭证/观测
  → P05 消息/历史/数据
  → P06 上下文/行为
  → P07 性能
  → P08 全产品/产物验收
```

为了让能力较弱的编码模型减少上下文冲突，默认不并行改多个阶段。阶段内部可以并行运行独立测试，但不能让两个实现同时执行同一任务或写同一份用户数据。接口真正独立后，未来可另行授权调整顺序；不能用并行绕过前置验收。

## 5. 成功的含义

完成不是增加多少Rust/TypeScript、拆多少文件或跑出多少绿色测试，而是：当前保留功能仍可用；每种核心事实有明确权威；工具和模型调用真实经过规定边界；实时/历史一致；失败可解释、取消可验证、恢复不重复副作用；新增能力只接入已有规则。

性能与模型准确性必须另有测量证据，不保证某个提速百分比，不保证模型永远选择正确工具，也不承诺绝对没有缺陷。对应阶段给出了比较方法和停止条件。

## 6. 证据、状态和权限

执行与验收使用[92_交付与验收模板.md](92_交付与验收模板.md)。缺实际测试、平台、凭证或产物证据写BLOCKED；不能以源码“看起来支持”替代。P00的通过是基线质量，P08的通过才是本轮全部必需验收完成。

本包的生成未修改GitHub仓库、未创建分支、未运行项目测试。实施端默认只做获准的本地阶段；远程push、PR、tag、发布、真实数据迁移与付费/外发测试需要明确授权。

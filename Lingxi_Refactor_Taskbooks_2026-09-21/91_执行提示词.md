# 配套执行提示词

## 1. 第一次使用：只执行P00

把整个任务书目录放到编码模型可读取的位置，将下面提示词直接交给它。无需一次粘贴九份正文。

```text
你现在负责执行灵犀现有技术栈架构重构的P00阶段。

先阅读00_README_总入口.md、01_通用执行约束.md，再完整阅读P00_基线、范围与验收地图.md，按需查90_源码依据与参考资料.md和92_交付与验收模板.md。

只执行P00，不进入P01，不修改生产业务行为。先读取当前仓库实际存在的AGENTS/贡献/测试规则，核对当前分支、HEAD、锁文件、运行环境和已有未提交修改。研究SHA只是参考，不得reset覆盖当前工作。

逐项完成P00-T01到P00-T08：清点当前采纳功能及排除项、追踪真实调用链和事实所有者、映射既有测试、建立安全隔离fixture、运行能实际运行的基线检查、记录性能与提示词预算、整理后续阶段的最小改动清单。已经正确的实现只验证，不安排重复建设。

本轮保留Electron/React/TypeScript/Node.js/Pi，保留四基础工具加按需目录，不恢复旧的强制子代理调度、独立知识研究和撤回的本地模型子系统。不升级依赖，不改UI，不修改真实用户数据，不用真实账户消耗预算或发消息，不push/PR/tag/发布。

每条命令记录exit code和原始日志。无法运行标BLOCKED，失败标FAIL，不能复制历史测试数字作为当前结果。基线问题应分阻塞、后续主责阶段和范围外建议，不能把所有问题都塞进P00修改。

完成后按92模板交付P00报告、结构化结果、功能/入口/所有权/验收地图、日志和P01交接。明确P00 PASS只代表基线足够实施，不代表软件没有问题。提交报告后停止，不自动推进下一阶段。
```

## 2. 之后执行某一阶段：模板

将下面“本次阶段”替换成用户明确指定的阶段ID和实际文件名。它是提示词模板，不是自动推进授权。

```text
本次阶段：P01；任务书：P01_模块边界、Pi适配与严格类型入口.md。

先读总入口和通用执行约束，再读本次任务书及上一阶段实际验收/交接。核对当前HEAD和研究基线差异；前置验证缺失就如实记录，不擅自越过依赖。

严格按本阶段任务ID逐项执行。每项先读真实实现和调用者，再建立或复用契约测试，进行最小实现/接线修改，运行测试，说明旧路径去向。已有正确实现采用UNCHANGED_VERIFIED，不为改动量重写。建议文件名不等于已存在API，不得编造调用。

不得新增平行Agent循环、工具网关、任务总管或凭证体系；不得回到全工具常驻；不改变用户采纳的权限、人格、MOOD、观测会话分组、知识来源、文件交付和历史行为。禁止通过降低类型/测试/安全要求获得通过。

仅修改本阶段必需的本地代码、测试与文档。不要push、开PR、tag或发布。测试隔离真实用户数据与账户。真实付费模型、外发和平台验证无授权/环境时标BLOCKED，继续本阶段其余可独立完成部分，不能虚报PASS。

输出本阶段每个任务和验收场景的状态、实际生产入口、改动/删除/保留文件、命令与exit code、原始日志、未完成原因、回退步骤，以及下一阶段交接。安全/数据/功能缺口未关闭不得声称本阶段全部完成。交付后停止。
```

## 3. 独立验收提示词

```text
你负责独立验收当前阶段，只审查，不修改生产代码。

先读原阶段任务书和通用约束，然后读取实际源码diff、阶段结果与原始命令日志。不要把实现者总结当事实。确认实际SHA、环境、测试范围和产物对应。

逐项检查：新实现是否真实可达；已有实现是否被重复造轮子；旧路径是否退出；参数、主体、生命周期和数据版本是否一致；测试是否经过真实入口并观察副作用；未运行是否被冒充通过；是否改弱断言、删掉历史兼容或修改旧审计证据。

针对本阶段至少尝试构造权限变更/迟到事件/并发隔离/重复结果/异常退出中相关的反例。验证脚本只在隔离临时目录执行，记录并清理临时文件，保留必要日志。不调用真实账户或改用户数据。

输出PASS、FAIL或BLOCKED及逐项证据。发现问题说明最小复现、实际后果、对应任务/场景ID、源码位置和最小修复要求；不要把无关优化加入本轮。没有发现问题也说明已做哪些验证及哪些边界未验证。不要承诺绝对无缺陷。
```

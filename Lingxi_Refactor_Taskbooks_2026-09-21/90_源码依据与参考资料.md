## 2. 官方技术参考

下面页面在本次编制时打开核对。它们解释相关机制，不要求升级到页面列出的最新版本。必须以仓库锁定依赖和实际运行时导出为可用API边界。

### E01｜TypeScript strict

严格检查的含义；不是业务正确性的证明。适用P01。

官方页面：`https://www.typescriptlang.org/tsconfig/strict.html`

### E02｜TypeScript exclude

exclude不阻止由import进入的文件被纳入工程。strict隔离必须检查真实依赖。适用P01。

官方页面：`https://www.typescriptlang.org/tsconfig/exclude.html`

### E03｜Node.js v24 Worker threads

CPU工作与I/O工作区别、worker池及跨线程约束。页面可能晚于锁定版本，只使用实际运行时支持的API。适用P07。

官方页面：`https://nodejs.org/docs/latest-v24.x/api/worker_threads.html`

### E04｜Node.js v24 AbortController / AbortSignal

取消是通知，实际操作是否退出需另行验证。适用P02/P04。

官方页面：`https://nodejs.org/docs/latest-v24.x/api/globals.html#class-abortcontroller`

### E05｜Electron Performance

先测量、避免主进程阻塞和延迟非必需初始化。适用P07。

官方页面：`https://www.electronjs.org/docs/latest/tutorial/performance`

### E06｜Electron Security

上下文隔离、沙盒、IPC主体等与Agent业务权限不同。适用P01/P03/P08。

官方页面：`https://www.electronjs.org/docs/latest/tutorial/security`

### E07｜SQLite Online Backup API

对运行中数据库采用一致性备份；具体按项目已有存储依赖实现，不为此更换数据库。适用P05/P08。

官方页面：`https://www.sqlite.org/backup.html`

## 3. 确认事实、建议与待验证项的区别

确认事实包括：现有网关与边界检查、现有Pi适配、现有规范化事件与有界streamId/seq缓存、当前后端非strict配置、当前用户会话观测复用规则，以及三种操作系统、四组平台/架构CI配置。

建议包括：九阶段顺序、证据模板、类型收紧范围、有限热点选择、默认性能非回归阈值和真实模型评测样本方法。这些都是本轮拟采用的执行要求，不是仓库已实现事实。

待验证项包括：全仓是否仍存在旁路/重复状态，真实性能瓶颈，全部供应商与平台的兼容，完整旧数据恢复。P00与各阶段明确要求实际调查/测试，本文不预先给出故障或完成结论。

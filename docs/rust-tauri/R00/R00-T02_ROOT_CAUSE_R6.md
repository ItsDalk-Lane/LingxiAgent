# R00-T02 第六轮失败后的独立根因分析

**结论：R6-F01/F02/F03 均阻断 R00-A03；不据此判 R00-T02 PASS。** R00-A04 的现役/撤回**静态分类 PASS**可作为下轮输入，不能代替 A03。分析基于 `codex/rust-tauri-migration`、HEAD `16aeb380d58d68ff1a38bb46f5cc5d18f985f084` 的现役源码和第六轮冻结候选。已对照本地 `AGENTS.md`、新任务书 R00-T02/A03/A04、R5/R6 独立审阅、`R00-T02_ROOT_CAUSE_R5.md`、人工分支契约、源码门禁、UI 动作矩阵及现役测试。本报告只提出修法；没有改候选、产品、测试、总账或任务书，没有提交、推送或运行未来迁移验收。

## 一、根因：三个“有记录”仍不等于三个“与生产一致”

R6 保留 832 条生产登记、736 个唯一叶和未执行子场景、26 个 UI 入口的 161 条动作与 281 条控件/效果变体，并补了最终消费者的源码范围。这些结构成果有效，但三处判断仍分别依赖**不完整的源码分支发现**和**未经逐项核对的文字结果**。`r00_t02_source_gates.py:139-146` 只把 `action === 字面值` 和 `switch case` 记为分支；`validate_ask_user_contract()` 只能比较已发现的集合。R6 独立内存反例在 `ask-user-tool.ts` 插入 `['skipped'].includes(action)` 提前返回，并同步逐叶及统一审查的源码/记录摘要后，完整 `build()` 返回 736 叶；改成 `action === 'skipped'` 则正确报新分支。摘要相同只能证明候选指向该版文件，不能证明其条件被理解。

`ConfirmStore.resolve` 可接收传入的 action；当前 HTTP 确实只允许 `confirmed/rejected`，定时器与中止还产生 `timeout/aborted`。因此 `skipped` 在当前 UI 是否可达尚须从所有生产者裁决，不能因 HTTP 枚举而让新增工具分流消失。现有 `<default>` 契约覆盖 `rejected`，并不自动覆盖一个会在兜底之前返回 `toolError` 的新分流。

另两项是结果 oracle 错误。`SettingsContent.tsx:392-396` 的 `loadProvidersSummary().catch(() => {})` 把摘要失败静默处理；`settings/actions.ts:63-65` 只有成功才更新摘要；`ProvidersTab.tsx:23-31,54-96` 未显示摘要加载错误，且挂载时不自行重拉（`ProvidersTab.test.tsx:497-509`）。但矩阵 `ui:settings:providers#01` 及回写场景要求“载入失败应有错误状态”。该话只可能适用于另行核实的配置加载错误，不能套在**摘要请求失败**上。`ProvidersTab.tsx:72-74,86-90,120-125` 的选择只更新 `selectedProviderId`，挑选未配置项还更新页面内 `draftProviderIds`；`ProvidersTab.test.tsx:120-141,147-183` 也区分选择和未保存草稿。矩阵 `#02` 把这两者与随后真正保存配置合在一条，只靠保存叶无法验选择后详情可见及草稿重开后的去留。

`AutomationPanel.tsx:135-199` 的“新增手动任务”在选到助手后明确发送 `prompt: ''`、`enabled: false`；HTTP 非成功走 `!res.ok` 的错误 toast，网络异常走 `catch` 的错误 toast。`server/routes/desk.ts:1132-1148` 只在**启用**的 Agent 会话任务要求提示词；`desk-route-cron.test.ts:740-783,785-825` 分别证实空提示词停用草稿创建成功、启用它失败。`AutomationCard.tsx:119-127` 在后来点击启用时阻止空提示词。矩阵 `ui:panel:automation#02` 却称“保存空提示词阻止”“HTTP 失败可能未单独 catch”，把新增、编辑、启用三个阶段混淆；`#03-05` 还复制同一套空态/失败文字，须分别核实。用量页 `#03-05` 反复写“八卡”，而 `ObservabilityMetrics.tsx:44-47,75-80,99-170` 的无数据与有数据分支均渲染十张指标卡。上述文字均回写到 `FEATURE_STAGE_ACCEPTANCE.json`，所以只修矩阵或只修回写场景一处仍会留下相反验收条件。

## 二、R6-F01：可实施的源码分支门禁

用仓库已有的 TypeScript 解析能力建立一个**独立于人工契约的 AST/控制流发现器**，由 `r00_t02_inventory.py` 在完整构建时调用；Python 校验器消费结构化发现结果。不要在现有正则上只增加 `includes`。第一步从 `const decision = await promise` 及其 `decision?.action` 建立带词法作用域的来源标记，传播到赋值、别名、解构、参数、返回值和可静态解析的本地 helper；同名但不是该来源的 `action` 不算。沿 `ask_user` 注册函数及所调用本地函数的调用图，记录到 `toolOk/toolError` 或其他外部可观察结果之前的每一条条件读取。对本地 helper 递归绑定实参，遇递归环、动态目标或未知副作用时停止并产生带调用点的 `MANUAL`，不能当作无分支。

第二步以 AST 节点建控制流图：`if/else`、三元、`switch`、短路 `&&/||`、`!`、`return/throw`、`break/continue` 和 `try/catch/finally` 都形成边；提前返回会终结该路径，而不是让后续兜底吞并它。对每条边保存路径条件、源码范围、原始表达式和结束时的结果签名。显式求值规则至少覆盖正反向 `===/!==`、常量数组 `.includes(action)`、常量 `Set.has(action)`、`switch` 字面 case、取反与布尔组合、可内联的纯本地布尔 helper；常量展开须按词法作用域确认未被修改。表达式一旦读取来源标记但不能可靠求值，例如运行时数组、动态属性、未知 helper、强制转换、正则匹配、反射或间接回调，就输出 `MANUAL` 候选，列条件、可能结果、消费者和原因，并使该入口的自动语义通过失败，直到独立人工裁决有可复核证据。不能把未知条件归入 `<default>` 或标为 `UNREACHABLE`。

第三步在有限符号域中计算路径：从源码出现的字面 action 值，加上当前已知生产者值、`null/undefined` 与 `OTHER` 哨兵；保守保留不能证明不可达的路径。值集合只是寻找候选的工具，不证明上游可达。对每条新条件建立稳定的分支身份（入口、条件源码位置/规范化谓词、受影响值集合、路径及结果），把**发现出的路径和值**与人工 `R00-T02_BRANCH_SEMANTIC_CONTRACT.json` 双向比较。契约逐项记录 `REACHABLE` 或带调用方约束及反证的 `UNREACHABLE_WITH_PROOF`、`SPLIT/SAME_EFFECT_WITH_VARIANTS/INTERNAL_STEP/UNREACHABLE`、成功/拒绝或错误效果、F-ID、场景断言。`<default>` 需有剩余域和实际结果，不能泛称“其他”。如果 action 未进入条件却直接改变返回值或副作用，也要记一条数据依赖结果；不能只找条件。自动生成的发现结果不可自动回写人工契约。

这样即使把逐叶、统一、聚合和源码 SHA 全同步，未改人工契约与场景的 `includes('skipped')` 反例仍会因**新增路径/结果无裁决**失败；若有人同时改契约，仍由未参与修复者对照上游与结果复审。源码摘要变化负责提示重审，AST 差集负责拒绝漏分支，人工证据负责判断行为身份，三者不能互相替代。

| 隔离样例（均只在内存变更并同步所有相关摘要） | 预期门禁结果 |
|---|---|
| `if (action === 'skipped') return toolError(...)`、`if (['skipped'].includes(action)) return toolError(...)`、`switch (action) { case 'skipped': ... }` | 三者都发现 `skipped` 的新结果路径；旧契约/场景不变时均失败。 |
| `if (!['confirmed'].includes(action)) return toolError(...)`；`if (isSkipped(action)) return toolError(...)` 且 helper 为可解析的常量比较；`if (action !== 'confirmed') return ...` | 分别展开取反、helper、反向比较及提前返回；记录 `OTHER/null/undefined` 的实际去向，不能误当只新增一个同效别名。 |
| `if (allowedActions.includes(action)) ...` 且集合来自运行时；`if (registry[mode](action)) ...`；helper 跨动态插件 | 产生定位明确的 `MANUAL` 且自动通过失败；人工核到生产者、可能结果及场景后才能裁决。 |
| 另一作用域内无关的 `action`、对来源 action 仅日志记录且不影响控制或结果、编译期证明不可达的矛盾路径 | 前两者不制造假“新行为”；最后一项只有保存可复核的路径约束证明后可裁为不可达。仍应把有结果依赖的日志之外用途纳入。 |

这也是过度报错边界：发现器关注从 `decision?.action` 到可观察结果的控制/数据依赖，不能扫描全文件同名词；同一纯 helper 被多个调用点使用时保留调用上下文，不重复要求多个叶；`['confirmed'].includes(action)` 若仅替代旧相等比较、路径与结果均等价，应允许人工契约更新源码条件后通过；无法证明等价时走 `MANUAL`，不凭文本相似性放行。

## 三、R6-F02/F03：从最终消费者重建 UI 的正反结果

| 对象 | 现役可观察事实 | 应改的候选断言与支持边 |

对**全部 26 页/面板、161 动作、281 控件/效果变体**执行同一种双向审查，而不是只补上表：从 `AppPages/SettingsContent` 等现役组合根沿 JSX、回调、hook、store、请求/桥和服务端处理追到用户能看见的状态、持久写入或外发；再从每个实际触发点（点击、键盘、挂载自动加载、刷新、定时器）反向查矩阵动作和变体。每条变体要独立填写“触发与输入→调用点→效果叶→成功读回/投影→空或未初始化→失败/无权限→适用场景”；同一按钮的**选择/编辑/保存/启用**若生命周期和结果不同，就分项。没有后端写入的本地交互可以接 UI 自身叶及场景，不为满足非空目标挂一个无关保存叶。场景断言从源码和现役测试独立核，不从矩阵文字复制；缺测试的关键分支可用定向组件/路由测试或可复核静态证据，不能把测试未覆盖写成已执行。检查相同断言被复制到多个动作、场景回写与矩阵是否逐字同步，只作为报警线索，仍逐项判断。

最终形成两个差集：**生产触发/消费者→动作变体→真实效果叶/场景**，以及**候选动作变体/支持边→生产触发和最终结果**。两边都必须空；动态目标保留具体 `MANUAL` 调用点、可能结果、人工结论和复审触发条件。`validate_ui_matrix()` 目前核 ID、文件存在、行号、源码交点和非空正反文字，尚不能判断“载入失败有错误状态”“空提示词阻止”是否真实；因此还须由独立审阅者逐行签认结果，并用少量有代表性的错误注入检验发现链，不能把 161/281 的计数或同步 SHA 当成语义通过。优先核共用初始化、配置与草稿、网络失败、权限、启停和删除等易跨阶段复制的行，但范围始终是全量 161/281。

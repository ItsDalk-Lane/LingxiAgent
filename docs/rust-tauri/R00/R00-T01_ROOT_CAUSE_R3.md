## macOS/POSIX 的删除能力与方案边界

[POSIX `unlink`/`unlinkat`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/unlink.html) 删除的是**目录项名字**；`unlinkat` 的文件描述符固定的是父目录，目标仍由相对名字在调用当刻解析。[Apple `unlink(2)`](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/unlink.2.html) 也描述为移除指定路径的链接。本机 `man 2 unlinkat` 列出的 `AT_UNIQUE` 只限制多硬链接对象，`AT_NODELETEBUSY` 只限制有打开句柄的对象；均不接受“仅当目标等于已知 `(dev, ino)` 才删除”的条件。调查这些公开的 macOS/POSIX 用户态接口后，**没有找到可按已持有文件描述符或已知 inode 原子地条件删除该目录项的 API**。这是对已查接口的结论，不宣称所有私有内核接口不存在。增加一次 `stat`、保留目标文件 FD、使用父目录 FD 或把 `unlink` 改成 `unlinkat`，都不能把“检查身份”和“删除名字”合成原子动作。

[POSIX `renameat`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/rename.html) 可在两个已打开的父目录之间原子移动目录项；Apple 的 [APFS API 文档](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/APFS_Guide/ToolsandAPIs/ToolsandAPIs.html) 列出 `renameatx_np`，[Apple 的卷能力说明](https://developer.apple.com/documentation/foundation/urlresourcevalues/volumesupportsexclusiverenaming) 指出 `RENAME_EXCL` 要由所在卷支持。本机 `man 2 renameatx_np` 也列出 `RENAME_EXCL`：目标已存在则报 `EEXIST`。方案须实际确认目标卷支持，再通过经测试的 libc 绑定或小型原生辅助函数调用带该标志的接口；普通 `os.rename` 默认可能覆盖目标，不能直接充当排他移动。`RENAME_EXCL` 只保护目标名字不被覆盖，**不**核对源名字是否仍是原 inode，所以移入后验证仍不可省。

可实施的清理次序：每个真实根目录预先排他创建随机命名、权限 `0700`、与哨兵**同一文件系统**的本次专用隔离子目录，并打开、核对它及根目录的身份；在哨兵建立前即登记清理意图。服务运行期间保持哨兵原位，完成原规格的前后摘要与哨兵检查。之后用根目录 FD、隔离目录 FD 和排他改名把哨兵名字**一次原子移动**到隔离目录的空名字；再以创建时保留的文件 FD/身份及隔离目录中对象的类型、`dev/ino`、权限、预期内容等核对。只有移入对象确属本次创建，且隔离目录仍是本次独占、未被替换时，才在隔离目录内清理，最后核对源名字与隔离目录均已消失。若移动的是外来文件或链接，**不删除**；仅在源名字仍空且能排他恢复时原子移回，恢复不了就保留在隔离目录并记录可找回位置及 FAIL/BLOCKED。若 `rename`/`unlink` 报错而操作可能已生效，重新核对源和隔离位置，仍不把异常折算为 PASS。隔离目录创建、关闭、最终移除本身也要登记和处理异常。

此方案保护的是任务书所需的安静窗口，以及其他 UID 无法进入 `0700` 目录时的普通替换和故障路径；不能承诺抵御**同一 UID 的恶意进程**在任意系统调用之间读取或改写同 UID 的隔离目录、替换源名字乃至搬走原哨兵。`0700` 对同 UID 不是强制隔离，随机名和前后 `ps`/`lsof` 也不是抵御这种对手的锁。源名字在原子移动**之前**仍可能被替换，方案的保证是“移入外来项时不误删，尽力无覆盖恢复，否则保留并失败”，不是保证恶意并发下原路径永远不被短暂移动。若要声称更强的对抗保证，须另有可执行的跨进程排他控制或 OS 级隔离，并给出相应反例测试；不能在本任务里凭多次 `stat` 宣称解决。目录摘要不是原子快照，安静窗口及发现变化立即失败仍不可省。

## `/tmp` 故障注入集合与复跑顺序

所有故障注入只在一次性 `/tmp` 夹具运行，不能在 `~/.lingxi` 或 `~/.lingxi-dev` 做破坏性反例；保存每例的前后名字、类型、身份、内容摘要、清理结果和退出码。替换对象使用合成普通文件、符号链接与指向另一合成文件的链接，禁止接触用户数据。

1. **创建事务：**`O_EXCL` 遇已有同名项；`os.open` 成功但首次 `fstat` 失败；零写/短写/写入异常；`fchmod`、`fsync`、读回、最终 `fstat`、文件 FD 关闭失败；父目录 FD 关闭在首目录和第二目录均注入“关闭前抛”和“实际关闭后抛”。创建后登记之前、第二目录失败时分别检查两目录；确认自建且未变的哨兵无残留，无法确认则明确报错、绝不按名字猜删。
2. **隔离层准备与收尾：**专用目录名字预占、`mkdir` 后身份核对失败、目录 FD 关闭失败、权限或同设备检查失败、隔离目录被链接/替换、最终目录非空、`rmdir` 或关闭失败。不得覆盖既有目录；异文件系统或缺 `RENAME_EXCL` 能力时须在哨兵创建前明确停止。
3. **移动与删除：**旧 R3 注入点 `stat→unlink` 的普通文件替换和符号链接替换必须在新方案中落在“最后核对→排他改名”窗口；另测改名已执行后抛错、目标名字预占、原哨兵搬走、内容/权限变化、移入后对象身份不符、`unlink` 已执行后抛错、源名字被重建。源目录中的外来对象及链接目标始终不被删除；不能恢复的外来对象留在隔离层并标 FAIL/BLOCKED，不能报告 `removed: true`。**同 UID 恶意进程在隔离层内最终核对与删除之间直接替换对象**也应作为剩余风险反例记录，不能以该反例通过作为安静窗口的放行条件，更不能宣称代码已消除它。异常清理也跑同一组，不只测正常收尾。
4. **扫描、状态与证据：**普通文件及子目录在 `stat→open` 间替换，链接在读取间替换，目录扫描期间变化，根目录被替换/换回，文件/目录关闭异常；注入第一次失败、第二次稳定，聚合仍保留同环境失败；日志/原始探针写入失败不能产出 PASS。保留现有 10 项回归并扩展上述缺口。
5. **A02 与总校验：**在 `/tmp` Git 副本中逐一修改原有未跟踪文件内容、增删改名、暂存无关文件、恢复旧删除项、改其他已跟踪文件、切换 HEAD/分支；候选目录内容保持不变，直接调用总校验器，逐例都须非零。另测候选目录增删改及证据哈希不符。

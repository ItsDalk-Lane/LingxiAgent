## 修正与根因

R3 的 F01 是哨兵已创建、但最后一次父目录关闭报错时，外层尚未登记它。现在先建立清理事务；创建、文件关闭和最后父目录关闭都处于同一异常路径，按已保存身份清理。首目录或第二目录失败都执行收尾。已实际关闭却报错时先 `fstat` 确认 FD 状态，不盲目再次关闭。

F02 是原 `stat → unlink` 之间可换掉同名对象。现在每个根目录先建立随机、`0700`、同卷的隔离目录，并以真实调用探测 `renameatx_np + RENAME_EXCL` 的排他语义。正常与异常清理共用排他原子移动；移入后核对类型、`dev/ino`、权限与内容，只有确认是本次哨兵才在隔离目录内删除。移入外来文件或链接时，若源名字空则排他恢复；不能恢复就保留隔离目录及找回位置并报告失败。移动、删除、目录收尾报错时均不返回清理成功。没有普通 `rename` 或按源名字 `unlink` 的退路。

F03 是总校验器只信旧 A02 结果。现在校验时只读重新收集 HEAD/分支、17 个旧删除及其二进制 diff、33 个原有未跟踪文件的集合与逐项哈希、暂存区和其他已跟踪差异；与首次快照、A02 结果、候选摘要对照，扫描候选前后各收集一次。候选目录仍动态枚举，按集合与逐文件哈希验证。

## 限制与复审重点

`0700` 与随机名不能绝对阻止**同 UID 任意恶意并发**访问隔离目录或在移入后再次换名。`/tmp` 反例显示：若同 UID 进程在移入后的最终核对与删除之间主动换名，仍可使外来项被删除而旧对象留在别处；不能把本机安静窗口的结果扩写成抵御该对手的保证。本方案在任务要求的安静窗口下工作，已发现的源名字或身份变化会失败封闭。真实目录摘要也不是原子快照。独立复审应重点核对排他改名能力探测、移入外来项后的恢复/保留、两种关闭异常的收尾、A02 的现场重算，以及候选清单与证据引用一致性。本次实测没有重启用户应用、迁移用户数据或执行真实外部供应商调用。

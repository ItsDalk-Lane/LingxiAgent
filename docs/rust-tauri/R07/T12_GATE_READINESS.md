## 具体不能原样复制的判定

1. `verify.rs::later_stages_of` 当前只过滤 `id != stage`，并未比较阶段先后。R07 处理 R02/R07 或 R05/R07 时会错误地把 R02/R05 当“后续”。`stage_map.rs` 对递延合法性的检查也只要求存在非当前阶段。未来应核实有序阶段 ID，真正后续为空就拒绝 share/deferred；本阶段应完成的义务不能退回已完成阶段。
2. 旧 `r02_share_satisfied` / `deferred_to_r07` 及 `r02Share/r07Share` 是 R02 的历史语义，不能在 R07 把“递延 R07”当成功退出。新地图应使用已存在的阶段中立类型，或明确的完整原行为类型。52 个跨后阶段叶保留原阶段集合和具体剩余责任；不能将整个原断言只变成一段 laterShare 文本。
3. 现有 `originalAssertionCases` 仅 `full_original_behavior` 可声明，且必须覆盖全部原断言；阶段份额种类尚无同等级的“原断言/条款→本阶段案例/后续责任”机器约束。要逐断言核算份额，需要补这个对应关系，不能伪报 full，也不能用宽泛份额文字避开本阶段应做的行为。
4. `lingxi.leaf-case-results.v1` 校验会复查所有 case 的唯一性、`ok=true`、整数 actual 与 expect 及地图图钉一致，并要求生产者本轮成功；但它本身不验证 `sourceCandidateSha256`、来源日志、入口/存储/结果等附加字段。来源核验须由受登记且有反例检查的生产者负责，不能仅加 JSON 字段便称机器已消费。
5. 当前 `RESULT_VERSION` 只接受 `lingxi.xtask.verify-stage.v1`。新增消费机制需要在解析器、结果和负向检查中正式实现；若改变既有字段语义应增结果版本并明确兼容，不可只在地图填任意版本。

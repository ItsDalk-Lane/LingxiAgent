## 任务书 5 条「怎么做」→ 设计硬要求

1. **预检**：版本/磁盘空间/可写性/旧实例状态/数据一致性/备份目标六项逐项取证；任一失败=不做半迁移（fail-closed，预检报告落盘）。磁盘空间预检阈值即 A10 的注入点——预检逻辑必须真实读取可用空间并与需量比对，不得用常量。
2. **停写与全局静止点**：停旧写者须获明确退出证据（进程退出+锁释放，非 instance.json 消失——STORAGE_READINESS 已警示旧二进制不认识 Rust 锁）；多库+文件的全局静止点：SQLite 走 Online Backup，文件走摘要比对，不能只保单库在线快照。静止点声明须枚举全部 69 类中在范围内的存储。
3. **隔离目录转换与验证**：调用 T04 CLI 在新隔离目录转换；验证=迁移收据核对 + 计数/哈希比对 + 只读端点抽查；写 migration receipt 与目标 epoch 后，原子切换活动目录/配置指向（rename/symlink 原子语义，不得先删后建窗口期）。
4. **自检后开放写入 + 断点恢复**：新服务自检通过前写入保持关闭；任一步骤中断可识别当前阶段（状态机落盘 journal，不靠 mtime 猜）并恢复/退回。
5. **单写者**：按 R01 策略验证旧发布程序不能再写新数据；不能保证 → 继续分离根且禁止共享写入（显式裁决记录）。

## A09/A10 验收要点

- **A09**：预检/备份/导入/指针更新/启动五断点逐一注入崩溃（kill -9 或等价），同一迁移入口重试；通过=总能确定有效数据根、旧数据保留、无两套写者。证据=逐断点恢复日志（journal 阶段记录）。

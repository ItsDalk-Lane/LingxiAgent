4. 定义安装/更新/禁用/卸载对 generation、描述快照、批准和执行句柄的影响；旧描述不得悄悄指向新含义。复用单一协议源生成 schema/TS，并进行跨语言样本一致性测试。

**R04-A01｜目录与执行同源：**注册两个来源不同的同名工具，经发现、描述和指定 target 调用，实际只命中正确目标；保留目录、调用及结果关联记录。T01 可用最小计数执行器，最终阶段再用真实能力复验。

**R04-A02｜陈旧目录拒绝错误目标：**客户端持有 generation1，工具改成 generation2 后提交旧请求；必须明确刷新或拒绝，不能执行语义已变的新对象。

**追加对抗检查：**别名与主名的权限一致；畸形 schema、过深参数、非法必填类型、伪摘要均不触发副作用；规范化碰撞明确处理，不制造第二工具身份。

### R04-T02：实现唯一工具执行网关

**目标：**不同调用路线不能改变同一主体、工具、参数应得到的授权结论。

1. 将当前已存在的直接、按需、MCP、插件、开发、子代理、后台调用入口转为统一请求；后续客户端只定义接入契约和调用级测试，不顺手完成整套客户端。
2. 依照 4.2 冻结 owner 和执行顺序，接入现有 RunSupervisor、授权上下文与 journal。`PreparedInvocation` 必须由服务端生成、不可由模型伪造，绑定主体/Run/目标代次/有效参数/资源/期限；执行时重验。禁止“approved:true”即可通行。
3. 补齐策略 service ports 和真实入口接线；未经配置的授权机制应拒绝其不能安全判定的操作，不自动 Full 放行。T03 实现完整批准生命周期；当前任务不要用假策略证明网关真实安全。
4. 对危险执行器入口做静态边界扫描和运行时负向验证，覆盖旁路调用、同源工具别名、嵌套 worker/MCP 回调。合法多层收窄允许存在，但不能出现任一路径单独放宽或写第二份调用收据。

**R04-A03｜各入口权限不变：**固定主体/target/参数，逐条适用入口运行允许、拒绝、需批准三组，权限结论与实际副作用一致；某入口确需更严格策略时登记依据，不凭“路径不同”绕过。

**R04-A04｜伪造执行凭证失败：**调用参数携带假的 principal/capability/prepared/approval，不能覆盖宿主认证事实、扩大授权或形成实际副作用。

**追加对抗检查：**摘要对应 A、真实参数为 B；同一批准并发使用两次；跨 agent/session/执行节点复用句柄；禁用后缓存句柄调用；每次都由真实网关而非测试替身决定拒绝。

### R04-T03：批准、撤销与只读模式

**目标：**批准的具体动作与实际执行完全对应，策略变化及时生效。

1. 迁移现役 operate/ask/read_only、预授权和子代理审批能力规则；完成 4.3 的 ask 继承义务。模型审批建议不能覆盖硬性拒绝；R05 真实审批模型未接入时，不能伪造模型批准。
2. 批准记录绑定有效参数摘要、真实目标、资源集合、调用主体、执行节点、Run、代次、期限、允许次数；提交和消费具有并发保障，不能两个并发请求各花掉同一次批准。
3. 拒绝、超时、取消、重复点击、迟到批准、权限修订、工具卸载必须有确定结果。等待期间不得预执行副作用；取消后迟到批准不能复活调用。重启后的旧批准按明确持久化/失效规则处理，不能默认延续。
4. 在真正派发前重新裁决可用性、身份和授权。明确“撤销先赢”和“操作已开始”的边界，不声称撤销可以撤回已完成外部操作。提供受认证的最小批准交互接口与真实链测试，不新做整个设置 UI。

**R04-A05｜批准后改参不能执行：**用户批准文件 A，提交时改成文件 B、改变正文或扩大资源范围；拒绝或重新申请，B 与未批准内容不得被写入。

**R04-A06｜等待审批期间禁用工具：**请求尚在等批准时禁用/卸载目标，再批准旧请求；仍不执行，错误明确表明目标或授权已失效。

**追加对抗检查：**父 read_only 的写权限请求、父 ask 且子代理不可人工审批、正常 operate 对照；批准超时与执行竞争；重启后票据重放；不同别名不得重复使用一次授权。

### R04-T04：原生读写改文件与资源权限

**目标：**`read/write/edit` 真正在 Rust 中执行，结果和授权对应实际文件。

1. 对照现役 schema 和行为，迁移读取范围/分页/编码/二进制处理、write、edit 匹配与冲突语义。保持真实输入完整，执行器不得根据 args_summary 猜正文。
2. 将 ResourceRef/路径、工作区和主体授权连到同一资源规则；处理目标不存在时的受控父目录、相对路径、符号链接、Windows junction/盘符/UNC 等适用情况。验证真实目标，不只检查字符串前缀。
3. 写入和替换采用平台可行的原子/可恢复方式，核验版本或内容摘要，防并发修改丢失；检查到使用的间隙用受控句柄/目录相对操作等可证明机制约束。不能仅 `canonicalize` 一次就声称无竞态。
4. 写入失败、磁盘满、权限拒绝和中断不得登记成功产物。保留未来 checkpoint/rewind 需要的明确接口，不提前迁移完整文件历史产品。文件确有部分副作用时如实记录，不能把错误等同“完全没发生”。

**R04-A07｜并发编辑不覆盖用户修改：**工具基于版本1准备编辑，用户改成版本2后继续；返回冲突且版本2不丢。重读/重试遵守原合同，不能自动覆盖。

**R04-A08｜符号链接不能逃逸授权目录：**测试工作区链接指向授权测试根中的外部受限哨兵，读/写/改按真实目标权限判定，越权无副作用；适用平台补 junction/链接替换竞态。

**追加对抗检查：**相似路径前缀、上级目录切换、空格/中文/Unicode 文件名、CRLF、长文本尾部、重复匹配、临时文件清理；非法输入应有合法对照，不能靠拒绝全部路径过关。

### R04-T05：命令、PTY 与真实进程树取消

**目标：**`exec_command` 与 `write_stdin` 具备真实交互和资源生命周期，不依赖 Pi 工具工厂。

1. 迁移现役 cwd、shell、参数、环境、输入输出分片、等待/返回句柄、退出码、截断与持续终端语义。返回“进程已启动/仍运行”不能冒称命令完成；write_stdin 必须校验调用者、会话和进程句柄授权。
2. 不需 shell 的操作使用结构化 argv；确需 shell 的命令保留原功能，以权限及 OS 隔离约束，不用关键词黑名单假装安全。环境注入最小化，不能把服务端全部秘密继承给工具或 MCP。
3. 建立或复用真实 ProcessSupervisor：按平台使用可验证的进程归属、句柄/Job/进程组及现役 helper；覆盖派发失败、取消前已退出、孙进程、管道、PTY 与清理超时。不得仅按裸 PID 或名称回收未知进程。
4. 取消请求、终止、等待退出、观察和登记回收使用一个有界清理责任链；普通调用 Future 被丢弃也不能丢失进程归属。持续终端若按原契约跨调用存在，必须显式登记寿命，不把合法持续进程全杀，也不把遗留进程冒称持续终端。

**R04-A09｜真实孙进程被清理且哨兵存活：**命令创建子/孙进程，另有无关测试哨兵；取消后受管树退出，哨兵存活，管道/PTY/许可回收，收据准确。必须在真实目标 OS 观察，不能只检查 CancellationToken。

**R04-A10｜PTY 交互不退化：**运行受控交互程序，执行输入、多次读取、resize、中断和退出；输入输出、尺寸、退出码和取消语义正确。

**追加对抗检查：**父提前退出但孙进程仍持有输出管道、输出风暴、UTF-8 分片、无响应进程、stdout/stderr 同时阻塞、跨主体 write_stdin、句柄过期/伪造、取消与正常退出竞争；按声明的隔离能力验证逃逸行为，不虚构平台保证。

### R04-T06：跨平台沙盒与逃逸防护

**目标：**真实限制执行资源，缺失保护时明确拒绝。

1. 从现役 PathGuard 和平台 helper 提取实际读写/网络/环境/子进程边界，复用可验证的成熟机制；不为“纯 Rust”重造已经可靠的系统隔离层。
2. Rust 负责安全参数和最小授权组装，helper 路径、版本、可信来源、必要完整性按已选方案验证。配置错误、不支持策略、缺 helper 必须失败关闭，不自动裸跑。
3. 以受控目录和回环网络探针验证实际允许/拒绝行为，包括绝对路径、链接、继承句柄、网络范围与临时资源。不能仅断言生成的命令行包含某选项就证明隔离生效。
4. 每个平台写明保证和不支持能力；运行时发现不能履行某次操作要求，应明确拒绝或请求合法能力条件，不能向模型谎报“已在沙盒中”。受限能力不自动获得用户额外授权。

**R04-A11｜缺沙盒不裸跑：**移除测试安装中的必要 helper 或换成不匹配版本，提交必须隔离的命令；拒绝、诊断清晰、外部哨兵不变，不回落无隔离执行。

**R04-A12｜隔离保证实际成立：**真实目标平台按其冻结策略访问受限路径、网络和环境；允许对照成功、禁止项实际受限，未具备的保证明确未支持。本阶段到期平台验证缺失不能记 PASS。

**追加对抗检查：**helper 替换、错误签名/版本、策略注入、绝对路径与链接改向、继承秘密环境；不能关闭 TLS、禁用全部工具或偷偷提权“解决”测试。

### R04-T07：MCP 与插件 worker 接入

**目标：**外围工具进入同一 Rust 授权、执行和恢复链，不形成第二内核。

1. 按 R01 锁定方案优先使用官方 rmcp，实际验证所需 transport、初始化/版本协商、分页工具清单、变更通知、认证与错误。只覆盖现役支持范围，不承诺所有 MCP 版本。SDK 存在不是集成完成证明。[W02]
2. MCP 工具描述、注解和结果均是不可信输入。来源+server+tool 的身份稳定；重连/工具变更更新代次、失效旧批准；远程会话 ID、工具名或返回路径不成为本地授权凭证。按协议验证凭证受众与用途，不能把宿主高权限 token 透传任意服务。[W03]
3. worker RPC 只接受最小单操作请求，带调用 ID、期限、取消、资源许可和大小上限；规范日志与协议通道，控制并发、启动和回收。worker 不读取整个用户 home、provider 密钥库，不独自构建 Agent loop。
4. worker 如需模型能力，保留受控宿主回调契约。R05 尚未实现真实 ModelGateway 时，合法返回“能力未配置”并测试拒绝/预算边界，不提前实现供应商、更不能让 worker 偷找 key 直接外发。代码隔离依赖真实进程/系统机制，同进程 Rust 模块不是安全沙盒。

**R04-A13｜MCP 重连不重复执行副作用：**受控 MCP 服务完成一次计数动作但断开回执，客户端重连；不能自动重发写调用，按 verified idempotency/status 查询或 Unknown 处理，计数不盲增。

**R04-A14｜worker 无法绕过权限：**worker 请求超出 grant 的文件或模型凭证，真实宿主拒绝；grant 不扩大、秘密不泄露、主服务仍可用。

**追加对抗检查：**两个 server 同名工具、tools/list 变化、错误/超大输出、结构化结果不符 schema、取消后迟到响应、跨调用复用 ticket、伪造本地文件链接；只对合成或明确获准实例测试，不自动启动用户所有外装 MCP。

### R04-T08：工具结果、产物与全矩阵验收

**目标：**将前七项接成真实可用工具链，并证明 R05 接入时不再依靠假的工具结果。

1. 统一 Success/Failed/Cancelled/Unknown 的外部语义与内部收据，明确是否派发、是否有部分副作用、是否仍运行；保留内容块、资源身份、截断和可重试性。不能“请求已发送”就登记“文件已生成”。
2. 文件产物登记前核验存在性、实际目标权限、基本格式或任务要求的内容条件；资源读取复用权限。MCP/worker 只声明成功而没有可验证产物时，拒绝假成功；远端资源按其类型验证，不强制假装本地文件。
3. 从实际注册的 Rust 工具、复用的单操作执行器和适用入口展开权限/生命周期矩阵。已承诺可用的路径都必须真可用；后续未迁移能力准确标识并保留期限。禁用/卸载时所有适用入口同受限制，无开发或延迟旁路。
4. 建立真实 Rust service/网关→文件/进程/MCP测试服务→收据/结果的闭环。测试 Provider 只负责发请求与检查得到的真实结果，不能按工具名自己伪造输出。验证四基础工具、权限拒绝、取消、重连、崩溃未知结果以及 R03 回归；关闭旧 Pi 工具工厂仍能完成新 Rust 路径。

**R04-A15｜空产物不算成功：**worker 返回 success，但文件不存在、越权或结构不满足约定；网关不得登记为已交付有效文件，错误和实际副作用事实准确。

**R04-A16｜禁用状态覆盖所有路线：**缓存工具描述与句柄后禁用目标，从全部适用入口调用，均不得新执行；真实已执行的历史结果保留，不能通过删历史掩盖事实。

**必须交接：**R05 能调用的真实工具目录/schema、参数载荷、授权/审批端口、取消所有权、实际结果、ResourceRef、MCP/worker 能力与限制、完整注册和回归命令。Provider 可继续使用测试替身；R04 不伪造“真实模型已兼容”。

```text
核对每个当前到期义务；不把 R05+ 功能倒灌为当前阻塞。

检查测试是否mock掉核心、过滤0、修改预期、只数日志或伪造产物。
至少独立重跑本 Task 两个基础场景的关键正反面及最高风险变体；
参数/身份/权限/取消/副作用相关路径必须真实验证，不能只看测试名。
发现共同根因时一次报告所有同族路径，不一次只点一个症状。
复测后再次核候选，报告阶段图或代码是否变化。

不得修改产品、测试、配置、阶段图或原始证据。
自写复测在隔离副本/指定目录，输出位置不得扰动冻结候选。

返回 VERDICT: PASS / FAIL / BLOCKED。
PASS要求全部当前到期义务有效通过、接线真实、相关回归有效、
无未关闭的契约阻塞，证据与候选一致。
每个finding给出ID、严重度、源码或重现、违反要求、后果、根因、
同类路径、修复要求和必须重跑的集合。
建议性优化单列，不为“对抗性”发明无关必改需求。
旧finding误判可凭真实反证标NOT_A_DEFECT，但必须说明依据。
写入 {REVIEW_REPORT_PATH} 后结束；下一轮必须换人。
```

## 九、三层检查必须分别有证据

### 第一层：普通逐项自查

执行者按每个 A-ID 与补充义务逐项记录前提、动作、预期、实际、命令、退出码、环境、测试数据、产物和来源摘要。至少同时有正常对照与失败路径，证明不是“拒绝全部”换来的安全绿灯。

检查真实结果：文件内容与路径、实际进程存活和退出码、RPC 请求计数、网关授权结论、journal 和规范化消息。不能只检查函数返回 success 或报告里写 PASS。

### 第二层：对抗性自查

执行者主动尝试推翻自己的修复；不能把普通自查日志换个标题再交一次。

按 Task 适用范围覆盖以下反例族，并记录具体参数和结果：

| 反例族 | 必须考虑的变化 |
|---|---|
| 工具身份 | 同名不同来源、别名、陈旧代次、卸载重装、规范化冲突 |
| 参数 | 合法摘要配错误载荷、缺字段/错误类型、默认值变化、超大嵌套、长文本尾部 |
| 授权 | 伪principal、跨会话/agent/节点、父只读/ask、缓存批准、多次消费 |
| 时序 | 批准后改参、撤销与派发竞争、等待取消、已开始操作、迟到结果 |
| 文件 | 前缀相似、链接/目录替换、并发编辑、磁盘满、部分写入、临时文件 |
| 进程 | 子孙进程、父提前退出、管道未关闭、PTY交互、异常终止、资源名额 |
| MCP/worker | 列表变化、断线重连、无回执、伪资源URL、超大结果、秘密外泄 |
| 恢复 | 未派发/已派发/已完成未回执、未知不盲重试、重启后去重及旧格式 |
| 结果 | success但无文件/空内容、运行中误报完成、截断不声明、真实内容无法读取 |
| 证据 | 旧文件、漏场景、0测试、门禁删映射、输入变化、产物与候选不符 |

优先 barrier、明确握手、注入故障点和固定调度，不靠随机 sleep 或复跑碰绿。只能对授权的合成目标攻击，禁止以测试名义访问真实未授权资源。

### 第三层：全新独立对抗性审查

Reviewer 独立读取并复跑高风险场景，而非审阅自查表后签字。修复后新 Reviewer 不仅检查上轮 finding，还检查整个 Task 的原要求与回归。

规范允许的替身必须明确标注；政策裁决、真实 I/O 与恢复不能被替身伪造。

### 缺陷、观察和阻塞分开

真实违反本阶段契约且可达的问题为修复项；纯建议、未到期后续义务单列。源码推导与动态复现分开写，不能把前者冒充实测。已知真实错误不能仅通过文档改写成为非阻塞。

测试失败不是环境阻塞；困难不是阻塞。但平台明确拒绝、缺少必要平台/工具/权限时不能伪造通过。之前某一会话受限不意味着当前环境必然受限；按当前权限核实。禁止通过换代理、包装命令、目录、编码或其他工具绕过平台拒绝。

两轮以上同根因反复失败，先派全新只读 ROOTCAUSE 代理汇总全部 finding、同族调用链和覆盖式修复矩阵，再派新修复者。不得降低标准，也不得同一候选同一环境无限重跑；无新进展且需要缺失决策/能力时保存断点，准确报 BLOCKED。

## 十、候选冻结、Git 与远程回执

每次独立验收绑定实际执行输入：源码、测试、配置、依赖锁、stage map、fixture、调用脚本及会被执行读取的契约。复用现役 candidate/runnerSourceBinding，不能再造一套冲突机制。

验收中和验收后执行输入变化：相关 PASS 变 STALE，重新生成候选并由新 Reviewer 复验。纯非执行性报告补录可单独核对，但不得把测试文件放进“证据目录”就自动从执行输入剔除。

Task Reviewer PASS 后，总控检查候选与待提交输入一致，执行 `git diff --check`，核秘密、大文件、测试产物和用户初始修改。按路径/hunk stage，禁止盲目 `git add -A`。

同文件混有用户修改，必须可靠分离；无法分离就停止该写入，不整文件覆盖/提交。禁止 `git reset --hard`、`git clean -fd` 和改写既有已推送历史。

提交信息包含 Task ID，例如：

```text
refactor(rust-tauri): R04-T01 establish tool contracts and registry
refactor(rust-tauri): R04-T02 route invocations through unified gateway
……
refactor(rust-tauri): R04-T08 verify tool execution and handoff
```

实际已存在的实现可以只补必要验证/接线，不造无意义代码变动凑提交，但每个完成的 Task 必须能从报告与提交链独立定位。

普通 push 到核实过的现有实施分支，首次确需 tracking 才设 upstream。确认远程引用/ancestry 包含本 Task commit 后才能记 DONE。commit 成功但 push 未确认记 `COMMITTED_PUSH_PENDING`，不进入下一依赖 Task。

远程分叉、认证、保护或网络错误要真实处理；不 force push、不悄悄 rebase 已接受历史。合法同步若改变执行输入，应重新验证受影响差异。

提交无法包含自身 SHA：源码提交 C 后由后续正常记录引用 C；接受记录提交 D 的 SHA 通过远程回执和最终报告记录，不再无限制造“填写 D 自己 SHA”的新提交。

## 十一、正式 Gate 与 R02/R03 回归

### 11.1 逐步登记，不做空壳门禁

复用 xtask，在 R04-T08 完成前建立真实 `R04.json`、注册 R04，并同步 runner 身份/图校验和实际生成器。早期可逐项登记，未完成任务诚实待执行；不得在 T01 就让整阶段空集合 PASS。

本阶段门禁至少覆盖原 `R04-A01～A16` 和所有到期补充义务。每一项有真正命令/测试生产者、真实输出和可验证断言。

未知阶段、空集合、过滤0测试、漏ID、删映射、跳过必需项、只有exit0但没产物、历史证据复用、候选漂移、执行器二进制与源码不符，都应非零退出。负向测试应在隔离副本进行。

不得只钉死“通过N个测试”而放任语义缺失；同时核对必需测试身份、行为断言和对应 A-ID。新增测试允许更新计数但保留旧保护；不能调小数字或删除场景让门禁变绿。

### 11.2 实际命令

按当前锁定工具链与本机支持执行，不自行升级 latest。以下是现有工程形态的基准命令，路径/分组确有变更时统一登记等价命令：

```bash

cargo clippy --manifest-path rust/Cargo.toml \
  --workspace --all-targets --locked -- -D warnings

cargo test --manifest-path rust/Cargo.toml --workspace --locked

cargo run --manifest-path rust/Cargo.toml --locked -p xtask -- check-contracts
cargo run --manifest-path rust/Cargo.toml --locked -p xtask -- check-boundaries

# 只有 R04 图和注册真实完成后才能运行并宣称有结果：
cargo run --manifest-path rust/Cargo.toml --locked -p xtask -- \
  verify-stage R04 --evidence <全新证据目录>
```

针对现役 Node/客户端/桥接消费者的改动，按真实脚本执行 typecheck、core-contracts、依赖边界、工具调用边界、相关测试与必要构建。不要猜命令存在；先读 package/CI。每 Task 跑影响范围，不每次附加完整安装发布流程。

依赖缓存不足不能把下载失败当产品失败，也不能把 `--offline` 失败写成通过；按环境许可补齐依赖或记录真实阻塞。顺序执行/分 crate 可用于可证明的环境资源冲突，但不能用测试串行化掩盖业务并发缺陷，必须保留原始失败及全部覆盖。

### 11.3 R03 回归是硬保护

最终候选必须重跑原 R03 Gate 及已纳入其中的修复套件；公共接口变化允许等价更新测试适配，但必须证明断言不降级，并保持旧数据库可解释。

重点保护：

```text
父先取消后建子节点与树传播；
普通取消在当前进程内清理busy、配额、监督和状态；
取消/终态统一裁决，迟到结果不能复活；
已派发无可信回执的Unknown，不伪造确认失败；
受理失败补偿、无幽灵Replay、不同内容冲突；
requestId规范化贯穿内存/持久化/重启，历史歧义明确拒绝；
前后台完整输入保真、超限明确拒绝；
后台steering只投到正确运行并实际消费；
子权限不得超过父权限，退出拒绝新任务。
```

R02 受影响的认证、资源范围、单写者、事务、事件快照/续传、备份、损坏库、关闭与 A15 重启链同样要回归。默认 Node/Electron 未静默切换属于 A16 保护，显式 Rust 工具测试入口不等于生产切换。

完整 npm/审计残留按现行已接受分类另记：GOV-01/GOV-02 不宣称已解决，也不无理由重开旧阶段；**新失败不得一概套用旧 seal 类别**，分类器/白名单不得为消红而扩大。

新增存储 schema 用版本化增量与注册表对账，不修改已发布迁移摘要，不直接操纵真实用户数据库。

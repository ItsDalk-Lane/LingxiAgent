# 输入、恢复与异步结果的生命周期

本文记录当前源码的跨模块约定。一次调用成功返回、输入写入、任务执行结束、结果交付是不同事实；不能用其中一个替代另一个。实现验证记录见[本轮报告](../../artifacts/architecture-contract-hardening/REPORT.md)，其他平台和真实供应商需要独立验收。

## 输入接受与取消

入口在 [desktop-session-submit](../../core/desktop-session-submit.ts)，实际 SDK 观察在 [desktop-input-commit](../../lib/pi-sdk/desktop-input-commit.ts)，执行编排在 [session-coordinator](../../core/session-coordinator.ts)。

- 尚未移交执行时发生明确失败或取消，可以发未接受回执；准备期取消使用 `input_cancelled_before_acceptance`。
- 已移交但没有写入证明时保持未知。输入已经写入之后，即使关联记录或广播失败，也不能倒退成未接受。
- 业务会话编号通过当前清单、路径和运行实例关联 SDK 会话；两种编号不要求字面相等。
- 插入消息等待 SDK 的异步排队结果，排队成功仍不等于写入成功。展示与来源记录属于该次输入，不能被异步等待间的其他输入抢占。
- 跨会话投递只在明确的未接受证据下更换发送方式，不能仅凭 `session_busy` 文案重发。客户端仍需要接受和结束两份证据才能释放队列。

## 记忆迁移与恢复

[迁移](../../core/pinned-tenets-migration.ts)与[恢复](../../core/pinned-tenets-recovery.ts)使用 v4 收据：`prepared → committing → target_committed → sources_archived → completed`。恢复不归档来源，其归档状态为不适用。

准备与原字节备份完成后，复查来源和目标；先写 `committing`，再原子写目标、核验、写已提交证据并收尾。只有 v4 `prepared` 能证明尚未尝试提交，并且仍须核对原快照不变。

`committing`、旧格式 `prepared` 和已提交状态只能凭完整目标证明继续收尾。目标缺项、正文变化或结果不明时保留资料并记录冲突，不重新执行导入。提交意图已保存但尚未写目标时被中断，也会保守进入冲突；重新尝试不等于重新批准。旧 `completed` 不驱动再导入，用户后续删除不会被恢复。

坏来源整体失败；真正的空数组与历史合法内容继续兼容。备份目录支持合法操作编号和旧 Windows 表示，同时拒绝越界路径。现有恢复命令的写入限制保持不变。

## 媒体任务与产物

[任务存储](../../core/media/task-store.ts)、[轮询器](../../core/media/poller.ts)与[提交编排](../../core/media/image-task-runner.ts)共用同一条结算规则：终态只结算一次，每次提交或重试拥有独立尝试编号，同一次尝试最多一个查询在途。同步返回、后台完成和重启恢复执行同一份产物检查——文件列表非空、文件真实存在、非零字节、位于生成目录内。

任务库只有文件不存在才从空库开始；损坏、非法结构和读取失败明确报错并阻止后续覆盖。正常关闭先阻止旧工作继续写入，再保存最新状态；保存失败必须反馈。交付复用持久记录，重启后只补未完成的交付，不重新生成。引擎关闭等待媒体查询与提交资源真实回收。

## 语音链路

识别请求带有独立的取消信号，经执行上下文传到网络请求和本地子进程；管理器关闭时等待本地资源回收。同一会话文件的多次识别拥有各自尝试身份，新尝试取代旧尝试：旧尝试的信号被中止，迟到结果不覆盖新结果，调用方收到被取代的明确答复。[识别服务](../../core/speech-recognition-service.ts)负责尝试登记，[原生协调器](../../desktop/native/LingxiSpeechHelper/Sources/LingxiSpeechCore/RecognitionCoordinator.swift)保存提前到达的取消或超时，挂接等待方时仍恰好结算一次。

语音参数由[唯一解析器](../../core/media/media-parameters.ts)决定默认值，工具入口保留显式空值，保证工具与接口调用一致。PCM 原始字节以 `.pcm` 文件交付，不改标为其他格式。

## MCP 连接归属

[连接管理器](../../core/mcp/manager.ts)让手动启动、按需启动和自动重连共享连接尝试。运行中的客户端实例是操作所有者；停止、替换、停用和管理器关闭使旧所有者失效。

启动、目录刷新、资源读取和工具调用在异步等待后复核当前实例及启用、认证条件。执行工具前还核对当前助手的权限。旧操作只能回收自己的连接，不能修改新连接的目录、权限注解或使用中计数。工具目录刷新、资源读取和工具调用都阻止空闲关闭。

## 文件版本与展示

[公共字段转换](../../server/session-file-block.ts)由实时交付和工具结果提取共同使用，传递文件身份、版本、大小、位置及可用性。[历史重建](../../server/routes/sessions.ts)可更新当前位置和状态，但保留当时记录的版本、大小与修改时间；缺少历史版本时不伪造证据。

[展示归一化](../../desktop/src/react/utils/content-semantics.ts)按已有版本及任务身份生成稳定编号。相同结果重放保留位置；不同版本、独立任务和明确的多次展示保留各自编号。多文件逐个保留，语音与图片、视频都参加历史结果重建。

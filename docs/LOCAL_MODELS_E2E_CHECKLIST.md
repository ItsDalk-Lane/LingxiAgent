# 本地模型端到端验收清单

这份清单只记录真实执行结果。没有模型、平台或凭据时写 `NOT_EXECUTED`，不要用单元测试代替。

## 准备

1. 使用 Node 24，确认 `node -v`、`npm -v` 和当前 Git 坐标。
2. 启动开发应用前设置独立的 `LINGXI_HOME`，不要复用真实用户目录。
3. 在设置 → 模型 → 本地模型中确认八个稳定条目均出现，首次启动不自动下载。
4. 记录系统、处理器、内存、应用版本、模型身份、精度、运行时版本和实际命中后端。

## 管理链

- 刷新远端清单；记录清单版本和来源。
- 下载一个小模型：暂停、退出应用、重启、继续；核对速度、剩余时间和最终 SHA-256 状态。
- 下载中断网；确认任务保留为可恢复状态，应用不崩溃。
- 分别导入一次带 `model.json` 和不带 `model.json` 的目录；后者必须出现身份确认，缺运行时选项不可用。
- 删除模型；确认二次确认显示释放空间，模型目录消失，已有向量数据仍保留。
- 尝试符号链接、路径逃逸、额外文件和错误哈希；必须拒绝且不留下可用登记。

## 四条业务链

- 嵌入：知识摄入、查询和记忆查询各一次；记录向量维度与稳定模型身份。
- 文字识别：图片、扫描 PDF、普通带文字 PDF 各一次；普通文档不得被错误改走识别。
- 语音识别：桌面录音、飞书或 QQ 原音频各一次；失败时原附件保留，微信无原音频时记录平台限制。
- 语音合成：助手回复朗读的播放/暂停/继续/停止各一次；Bridge 开关关闭时只发文字，开启时文字先到、语音失败不影响文字。

## 生命周期和安全

- 同时发起两种大模型各 10 轮；持续采样实例和进程，任意时刻只能有一个大模型。
- 取消排队、加载中和推理中请求；记录停止耗时，目标为 1 秒内；确认无孤儿进程。
- 等待小/大模型空闲回收时间；确认引用为零后卸载，并记录前后常驻内存。
- 推理期间断网；四能力仍应工作。只有清单刷新和资产下载可以访问外网。
- 杀死 sidecar；确认最多自动重启一次，同因再次失败后明确报错。
- 检查日志：不得出现文本、图片、音频、令牌、下载地址或用户绝对路径。

## 性能复跑

```bash
LINGXI_HOME=/absolute/test-home \
LOCAL_MODEL_BENCH_IMAGE=/absolute/sample.png \
LOCAL_MODEL_BENCH_AUDIO=/absolute/sample.wav \
npm run benchmark:local-models
```

输出只含模型身份、运行时、冷热耗时和进程内存变化。缺模型或样本的能力会明确输出 `NOT_EXECUTED`。

## 打包矩阵

- Windows x64、macOS arm64、macOS x64、Linux 构建各跑一次生产包。
- 从解包产物确认模型权重数量为 0；只允许目标平台原生依赖，不得夹带其他平台二进制。
- 每个平台启动生产包并完成原生画布加载、一个进程内模型和一个 sidecar 模型 smoke。
- macOS 检查应用和 sidecar 签名/可执行位；Windows 确认无需另装运行库；记录安装包体积增量。

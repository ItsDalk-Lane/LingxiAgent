# F04 严格检查修复

本轮核心实现进入 strict/noUncheckedIndexedAccess/exactOptionalPropertyTypes 实际闭包：17 个精确入口、28 个项目源码/声明文件；外部类型依赖另列，不冒充项目覆盖数。最终清单由实际编译程序生成，见 STRICT_SCOPE.json。

TaskRegistry 全写入口、有限 TaskStatus 分类表、真实总线、任务身份铸造及执行批次句柄；HTTP JSON/字段解析；WS 身份接纳；工具参数验证/权限分类；会话清理及实际 Pi shutdown 均直接受检。React 的 manager、恢复服务和接收分发继续由原严格 renderer 工程检查。大型旧路由直接使用受检解析器，后台命令/回档/子代理直接使用受检且冻结批次的句柄；媒体回执按 unknown 校验后绑定，生产消费者列入清单。没有另建任务管理器或维护第二份生命周期。

原六入口不足的审查成立。原 P08 把新 options:any 归为旧债务的理由撤销。更新后的 TaskPatch/AttemptOptions/TaskRegistration 与 SessionCreateInput 等为实际消费类型。后台 registry:any 和回档 getTaskRegistry:any 也已替换为真实 TaskRegistry 的窄 Pick；捕获批次/终结操作在真实 strict 模块内执行。新增句柄负例证明 attempt 只读、回调不能另传批次、媒体注册表批次和媒体批次不能传字符串。

门禁不再丢弃无 file 的全局错误，区分根入口与实际依赖闭包。损坏/缺失配置、缺失精确 include、缺失实际源码导入都明确失败。编译器 host 内存故障注入只供测试，不覆盖生产文件。删去真实 STATUS_KIND 中 aborted 分类会触发 TS2741；真实 query 可空访问须产生 TS2531/TS18047，不能用不存在的方法报错替代。

先红后绿日志在 main/f04-gate-red、strict-expanded-first、f04-complete-check 以及 f01/cross-review-*、typed-callers-*。复核曾发现空值负例误写 get，以及 TypeScript 默许遗漏精确 include；二者均已修复并独立复验。最终全量记录另见 FIX_RESULT，不累计多轮测试数字。

剩余显式 any 精确到行列于 STRICT_SCOPE.json：旧 schedule 动态载荷/筛选、旧日志递归脱敏和通用读取 helper。它们不豁免新 Task/attempt/创建参数契约。shared/safe-fs 唯一新增第三方动态装载先接 unknown，再检查模块对象及 load 函数；锁定 js-yaml 无类型声明，没有伪造本地 .d.ts。旧宽松读取返回没有虚称全严格化，注册表实际调用的 atomicWriteSync 受检。Pi shutdown 使用锁定 SDK 的真实 reason:'quit' 契约，并由真实 emit→unsub→dispose 测试证明接线。

未新增 @ts-ignore、@ts-nocheck、双重断言、白名单、依赖或配置降级。测试夹具中的故意错类型只经门禁额外编译注入；正常工程排除夹具是既有规则，真实实现没有被排除。遗留未重构面及第三方边界与真实消费者均在严格范围账本逐项保留。

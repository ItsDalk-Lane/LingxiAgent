## 结论

本分支把同一个工具经不同入口调用时的身份、权限、参数、生命周期和执行结果收拢为一份事实。直接展示、延迟目录、插件开发聊天和本地开发 HTTP 只是不同前台，最终都进入同一个受控执行入口；入口不能自行改写权限、挑选凭证或绕过审批。

- 固定基线：`60d910b84572c525a7c9c49216fb9206623bf7a4`（v0.1.34 发布提交）。
- 执行分支：`fix/tool-contract-path-invariance-v0134`。
- 原证据分支 `fix/tool-contract-path-invariance` 保持不动，只作为迁移参照。
- 源码候选和审计封印的真实 SHA：按 Git 自引用限制，记录在 `PROGRESS.md` 与最终执行报告；机器事实中固定为 `null`。
- 实施范围：任务书 P0-00 至 P11-02；最终验证、构建和封印由 P12 完成。

## 基线校正原则

最初证据链基于 v0.1.34 发布前提交。校正版没有推倒重写：旧分支保持原样，约八成不重叠成果按编号迁移；18 个重叠文件逐项与正式发布代码核对，11 个真实冲突只迁移仍缺少的契约语义。v0.1.34 已删除的旧知识执行路线没有恢复，所有测试和统计都在正式发布提交的后代上重新取得。

## 核心变化

1. 每个工具先建立稳定业务身份、完整参数校验、规范权限和生命周期代次。
2. 当前代理看不到或禁用的目标先被排除，再决定直接展示还是放进延迟目录。
3. 目录只保存目标引用和只读描述，不保存原始工具对象或执行器。
4. 直接、延迟、开发聊天和连接器调用都进入同一个网关；执行前复核参数摘要、会话、代理、调用编号、代次和实时可用性。
5. 插件和连接器卸载、禁用、重载或重连会让旧代次失效，旧会话不能继续执行陈旧对象。
6. 媒体入口统一解析执行目标和凭证来源；正式快速/详细知识路线统一消费完整重排策略，且不恢复已退役路线。
7. 语法树边界扫描把允许接触底层执行器的位置固定为精确文件白名单。

完整不变量、时序、路径和接入规则见 `docs/architecture/tool-invocation-path-invariance.md`。

## 安全与诊断边界

- 目标不存在、不可见、按代理禁用、已撤销、能力不匹配、凭证缺失、凭证解析失败、传输失败和取消分别保留稳定原因。
- 面向模型的错误会清除常见密钥、令牌和内部路径。
- 网关诊断只记录路线、来源、稳定目标、代次和错误码等安全字段。
- `npm run check:tool-invocation-boundaries` 扫描底层连接器调用、底层插件调用、桥接旧旁路、引擎原始对象映射和网关外规范执行器调用。

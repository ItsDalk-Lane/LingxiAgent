## P0：快速检索

完成独立的快速执行策略、冻结范围编译、本地全文检索、精确原文摘取与统一装填。发送时冻结笔记本及来源版本，查询只读目录元数据和命中块，不现场扫描全部原文或重建索引。普通发送及插入发送都使用同一快速入口。界面显示本地检索、证据数量、耗时和截止原因。

新增主要模块：`shared/knowledge-execution.ts`、`shared/knowledge-evidence.ts`、`lib/knowledge/scope-snapshot-compiler.ts`、`fast-knowledge-pipeline.ts`、`evidence-span-extractor.ts`、`evidence-packer.ts`。修改引擎、会话提交、知识管理器、五语言文案和过程显示。

生产流程：冻结资料 → 一次本地搜索 → 定点读取命中原文 → 原文片段装填 → 主会话回答。远程模型调用为 0；总期限 1200ms；最多 8 个片段；每段最多 320 tokens；渲染总预算 2400 tokens。超时、无证据、不可用来源均明确标注，不偷偷调用旧远程链路。

P0 数据版本：事实库保持 v17、全文索引保持 v2。快速入口退出旧辅助模型和大预算路径；历史消息读取继续兼容。

## P1：统一搜索与向量加速

新增 `knowledge-search-service.ts`、`query-embedding-cache.ts`、向量后端接口、HNSW 后端及独立 ANN 目录。搜索、读取、目录、逐字查找使用同一冻结范围；查询嵌入按模型配置和问题去重，所有来源合并后按模型组各重排一次。工具搜索结果只作线索，必须进一步读取才能成为证据。

生产流程：冻结范围 → 统一搜索服务 → 本地全文索引及按模型分组的向量召回 → 名次融合 → 可选全局重排 → 返回线索。主向量后端为 `usearch@2.26.0`；原生扩展不可用、加速索引损坏或待建时显式使用精确后端，保留原付费向量 BLOB。查询不等待后台重建，不伪造“已加速”。

P1 数据版本：事实库保持 v17、全文索引升至 v3，新增查询就绪的分块变体元数据；ANN 目录 v1。修改知识管理器、原文工具、向量存储、检索配置与发布依赖；旧重复查询入口在 P3-07 统一退役。

## P2：有证据台账的多轮研究

新增 `lib/knowledge/research/` 下的研究存储、需求台账、轮次执行、停止条件、共享预算、上下文渲染和提示词，以及真实阅读凭据服务与研究工具。修改 Agent、隔离会话协调、祖先范围校验、引擎及会话提交。研究过程仅发送查询、计数、状态等元数据，不暴露私有推理。

生产流程：冻结资料 → 根研究会话列目录并建立证据需求 → 按缺口搜索与委派 → 阅读原文取得凭据 → 宿主核验精确引文并入账 → 按台账判断是否完成 → 只把核验后的原文交给主会话。普通模型回复不能自行宣布完成，搜索摘要不能直接作为证据。

上限固定为 4 轮、4 个并行工作会话、32 次工具调用、180000ms；失败调用计入预算，恢复不重置额度或总时限。跨范围、伪造凭据、引文不匹配均拒绝。取消、超时、停滞、冲突和证据不足如实保留终态，隔离会话退出后清理，不写入主会话历史或长期记忆。

P2 数据版本：事实库升至 v18，全文索引保持 v3、ANN v1。详细回答正式发送和插入发送都退出旧一次性注入流程，恢复时只读持久化证据和动作状态，不恢复私有推理。

## P3：完整性与分层检索

新增完整性意图判定、执行器、分片规划及两个专用后台工具。完整性分母来自冻结原文单元，已读且核验的单元才能计数；读完所有可读部分仍不代表不可读部分已核查。缺页、扫描未识别、解析失败、工作会话失败、范围变化都使完整性声明失效。否定结论与“全部”措辞受宿主核验结果限制。

分块固定为 512 tokens、重叠 64 tokens；父章节最多 8192 tokens。索引按来源、章节、片段三层建立。搜索先缩小来源和章节，再在选中章节内查片段；章节向量精确补查先按片段编号过滤，查询嵌入复用。读取支持父章节和有限邻接窗口，始终回到真实原文与偏移。旧分块在后台逐批建立新版本，期间继续可读；旧付费向量和历史引用不被覆盖。

质量门禁覆盖全部人名、绝对否定、章节变化、全部反例、不可识别扫描、解析失败、重复事实及单源冲突。性能产物记录来源/章节/片段真实索引规模、冷/热查询、向量加速与精确回退、研究轮数和调用耗时。最终合成使用真实会话和本地 HTTP 测试供应商；不把脚本模型与声明的 token 数冒充在线付费模型质量或账单。

P3 数据版本：事实库升至 v19、全文索引升至 v4，ANN 仍为 v1。修改原文分块、摄入、索引、统一搜索、原文提取、研究执行、证据清单与打包验证。来源不可用、完整性不足和加速失败分别保留明确状态，不使用一个笼统成功状态覆盖。

# 语音独立进程修复与本机复验

日期：2026-09-03。范围：用户批准两项语音从进程内运行改为受控独立进程，解决卸载回收与可靠取消。当前工作区未提交，未发布；不是全部模型、全部平台验收。

## 结论

两项语音的原生计算和内存均移入子进程。取消、超时或推理错误发生时，父进程等待该子进程真实退出后才结束调用；下一条请求重新加载。排队撤回不终止正在执行的其他请求。正常卸载和宿主意外退出也会回收语音子进程。

仍按小模型管理，不占嵌入和识字的大模型名额。不向日常配置自动迁移，也不把旧进程内包伪装成新包。

## 实现边界

- 新增 `scripts/local-models/sherpa-sidecar.mjs`：只使用标准管道，不监听网络；随机令牌握手、身份来自运行包元数据，继承已过滤的环境。模型正文和音频不写日志。
- 原生工作线程留在语音子进程内部；禁止强杀宿主进程内原生线程的规则仍保留。必要时终止整个独立子进程，不会销毁宿主里的原生环境。
- `SidecarManager` 对语音串行处理，活动请求失败后等待进程退出；排队请求取消不发往原生层。其他类别默认取消行为不在本轮改动范围内。
- 重载后的进程编号实时读取，避免使用已退出进程的编号采样内存。正常退出后清理退出期限计时器。
- 长音频响应允许最多 64 MiB 协议消息，实际音频最多 47 MiB；超过上限明确失败，不截断为成功。仍为完整音频，不是假称原生流式输出。
- 隔离包 `sherpa-onnx/1.13.7-local2/darwin-arm64` 明确 `kind=sidecar`，入口为包内 Node 24，参数为 `sherpa-sidecar.mjs {threads}`。33 个文件逐份复核摘要；两个模型权重身份、文件摘要和小档分类不变。旧 local1 包保留作历史对照。
- 旧元数据缺省推断保持兼容；新正式分发包必须显式声明运行种类、入口与参数，不能仅更新适配器后声称旧安装已迁移。

## 真实验证

环境：Apple M3 Ultra / 96 GiB / macOS arm64 / Node 24.16.0；固定 4 线程。全部模型、运行包和测试输出仅位于 Downloads 的独立验证目录。

严格回收口径：每轮加载前记录宿主驻留，推理完成后记录宿主与语音子进程驻留总和，卸载返回即确认原进程不存在，500 ms 后再次采样。回收率 = 1 − 卸载后正驻留增量 / 加载后驻留增量。没有主动垃圾回收、隐藏进程、只清空逻辑引用或修改验收阈值。

两项各执行六轮；首轮完整复验均超过 95%：识别最低 97.948%，朗读最低 99.650%。最终源码又独立复跑六轮，结果如下（驻留不是峰值统计）：

| 最终复验 | 每轮回收率 | 五次取消耗时 | 进程退出后再使用 |
|---|---:|---:|---|
| 语音识别 | 99.171%–99.995% | 5.439–6.981 ms | 全部成功 |
| 文字朗读 | 99.487%–99.986% | 6.003–6.967 ms | 全部成功 |

最终原始报告为 `results/speech-process-stt-1788388600647/report.json` 和 `results/speech-process-tts-1788388613903/report.json`。宿主基线分别 188.61/188.66 MiB，全部实验结束后 200.06/202.80 MiB；没有将宿主正常堆缓冲的少量驻留误报为零。

- 每项五次长输入取消：输入为约 56 秒录音或重复长句，热加载后开始调用，50 ms 后发取消。所有返回前原进程均已退出，所有后续调用成功并产生新进程编号。
- 完整长音频：最终轮第二音色生成约 31.27 秒，1,501,240 字节，超过旧 1 MiB 上限仍完整返回并落盘。
- 空闲卸载：测试将小档空闲期限改为 100 ms，等待后既无逻辑实例，也无原语音进程。默认五分钟期限未等满，不冒充执行。
- 断外网：系统沙箱禁止所有网络，仅允许本机 Unix 管道；识别、两音色朗读、卸载与重载全部成功。沙箱禁止进程监测，相关内存数值仅宿主，不作为进程树内存证据。
- 宿主意外退出：只向本次创建的隔离宿主发送 SIGKILL，识别/朗读子进程分别在 27.32/44.89 ms 内随管道断开退出。首次探针的脚本换行错误未执行到模型，失败证据保留，不计通过。
- 四能力并发与回转：嵌入/识字十轮交替并发通过，大档原生进程最大 1；两项语音与大档同时存在，合成音频再识别得到原句。该实验小档预算 4096 MiB、大档空闲 100 ms，不代表默认并发预算验证。单语音六轮实验则使用默认 1536 MiB 预算。

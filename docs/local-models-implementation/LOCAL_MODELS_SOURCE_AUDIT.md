> 本文为 Phase 5 合同/源码审计快照，PASS 不能代替真实模型验收。Phase 6 已添加实际运行适配并发现回收/取消问题；当前证据边界见 [本机真实验证报告](LOCAL_MODELS_REAL_VALIDATION_REPORT.md)。

## 审计结论

源码已经形成一条可追踪的完整控制链：用户在设置页选择或导入模型，资产层校验并登记，业务入口以稳定身份提出请求，运行管理器评估内存和槽位后加载实例，推理结果回到原有知识、文档或语音服务，可观测层记录模型、精度、后端、耗时和内存。云端路径保留，只有明确选择 `local:` 身份时才进入本地分流。

当前源码没有内置真实权重和真实 sidecar 二进制。目录占位与假运行时只用于合同测试；生产可用性取决于后续发布的签名清单、逐文件摘要、许可证和平台运行时。

## 主要安全性质

- 模型身份由清单版本和精度共同决定，不能用同名目录偷偷替换。
- 手动包的完整性状态保持 `unknown`，不会冒充远端已验证资产。
- 解压只允许清单中的相对路径，不允许写出 staging 或受管模型目录。
- 原生运行时必须经过平台、版本、入口文件和逐文件摘要复核。
- 子进程环境采用允许列表，通信带随机令牌，协议错误和超大消息会终止实例。
- 取消和退出会关闭会话、停止子进程并清理临时安装目录；日志不记录令牌、音频正文、识别正文或模型原始输出。
- 本地路由沿用 `local-owner` 权限，只允许本机所有者操作。
- 内存不足返回结构化拒绝和缩小精度/关闭模型建议，不依赖 OOM 崩溃兜底。

## 打包审计

- Electron 应用本体不收集 `models` 或 `runtime/local-inference`。
- 独立 server 只携带业务源码、目标 Node、依赖和签名种子；画布仅保留 darwin-arm64 原生绑定。
- 最终应用目录约 646 MB，服务器种子约 171 MB；两者权重文件命中为 0。
- macOS 本机使用一次性测试 keyset 验证种子签名，随后逐文件删除临时密钥。
- 应用只做 ad-hoc 签名；正式 Apple 签名和公证不在本次权限与环境范围内。

## 审计限制

- 没有审计任何尚未提供的真实权重、运行时二进制或 GitHub Release。
- 没有动态抓包证明真实第三方 sidecar 永不联网；当前结论来自本仓库编排源码、协议合同和测试夹具。
- 没有用真实模型测量输出质量、语言覆盖、音色、向量维度或终止时延。
- 没有三平台实机，跨平台合同测试不能替代原生加载。
- 没有执行源代码行覆盖率统计；以专项合同、业务回归和全量测试结果作为当前证据。

## 已核实因果链

1. 本机 SDK 为 0.84.1；其公开返回契约要求 `runtime`。空扩展列表不代表可以省略运行载体。
2. SDK 在构造会话时无条件绑定运行接口；缺少载体时写入 `sendMessage` 即同步抛错。独立纯内存对照已复现精确错误；只补空对象仍失败，官方工厂创建的载体绑定成功。
3. 研究根会话、研究子会话和完整性检查子会话共用这个覆盖，三者受影响。正常进入这里的请求在正式提问之前失败。
4. 外层把隔离执行错误转为通用失败，两轮连续严重错误且无证据便终止；引擎随后生成截图中的错误。这说明截图是下游症状。
5. 原测试替换了整个会话创建函数，还把缺字段的对象作为正确预期，未经过真实 SDK 绑定。新增回归必须经过生产会话协调器和真实 SDK。
6. SDK 构造与返回阶段会重复读取扩展结果；每个隔离会话应创建一个新的空载体并稳定复用，不能继承普通会话载体，也不应每读一次就新建。
7. Git 逐行追溯确认问题覆盖来自 `faad0da24`，提交时间 2026-09-04 12:00:09 +0800。

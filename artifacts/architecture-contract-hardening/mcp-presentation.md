# MCP 与文件展示补强

基线：e0afc0dc3b94bc9763d715f981d6f948d1c39c27。以下测试在独立工作区、Node 24.16.0 执行，未使用真实连接器、供应商或用户历史。

## 已确认问题与修改

- MCP 原有按需启动去重不覆盖手动启动/自动重连；旧启动失败无条件删除当前客户端，旧目录结果可覆盖新目录与实时权限注解。现在三个入口共享连接尝试，异步完成核验实例归属、启用与认证，旧尝试仅回收自己。使用客户端实例作为连接代次，不增加持久配置。
- 目录刷新未计入在途工作，会被空闲停泊。现与工具/资源调用一样成对计数，旧实例的 finally 不影响新实例计数；死亡/停泊/停止清除旧权限注解。
- 正在建立连接的合法工具可以等待同一尝试；真正执行前重新检查助手配置，期间撤销使用权时不调用外部工具。管理器 dispose 后不能按需重启，只有显式新生命周期 start 才重新启用。
- 历史结果提取丢失文件版本，历史目录回填又把旧版本改成最新版本；语音结果被历史分类器遗漏。新增共用文件字段转换，目录回填仅改定位和可用状态，旧记录没有版本就不伪造。
- 同文件多版本或独立展示原先生成相同界面编号。编号现在含已有版本与任务身份，普通重复展示使用确定性序号，归一化重放稳定。

## 失败证据

- mcp-red.log：五个真实 McpManager 回归全部失败，覆盖并发启动、旧启动失败、旧目录覆盖、刷新中空闲停泊、停用后的迟到目录。
- mcp-connecting-red.log：合法连接建立中被提前判不可用。
- mcp-authorization-red.log：连接等待期间撤销助手工具权限后仍执行。
- presentation-red.log：五个回归全部失败，涵盖版本提取、展示编号以及图片/视频/语音经真实历史路由重建。历史使用临时 JSONL，读取/结果解析/路由及前端归一化均为实际实现。

## 当前验证

`mcp-presentation-green.log`：12 文件、476 项通过，包含上述反例及 MCP lifecycle/reconnect/runtime/routes、桥接调用、block extractors、sessions route、content semantics、chat slice、stream buffer。

两处旧测试调整有明确原因：一处自动启动测试等待真实启动后才替换测试客户端，避免在后台启动过程中伪造实例；明确 stop 后必须显式 start，不能让 refresh 偷偷撤销停止。展示测试更新为带任务身份的编号。未删除原有拒绝/数据断言。

实际外部连接器、其他系统及发布物尚未验证。完整集成门禁待其他分组完成后运行。

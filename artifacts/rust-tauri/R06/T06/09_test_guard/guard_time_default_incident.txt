##### 守卫默认时限 300s→600s 的依据（R06-T06-FIN2 收尾实测）#####

现象：守卫以默认 TEST_TIME_LIMIT_SEC=300 中止既有用例
  r04_t08_tool_matrix::approval_face_share_cases（SIGABRT @ 300.02s，内存仅 37MB）。
  共复现 3 次：
  1. 第三棒全量回归（/tmp/full-suite3.log → 06_workspace_regression/full_workspace_final.log
     第 1711-1733 行）：r04_t08_tool_matrix-78caeffafceb3c68 abort @ 300.03s
     （注意：第三棒的 full_suite_result.txt 摘要只记录了 PTY flaky，漏记此 abort——
     该二进制被 SIGABRT 后无 test result 行，按 test result 行统计会漏计）。
  2. FIN2 定向重捕（/tmp/t06_targeted_final.log 尾部）：r04_t08_tool_matrix-dd95be5104c67a3b
     abort @ 300.02s。
  3. FIN2 单跑（hooks 生产默认 ON）：abort @ 300.02s（/tmp/t06_approval_single.log）。

根因（不是失控、不是 T06 回归——是守卫默认时限对既有合法用例误伤）：
  该用例固有耗时 ~300.5s，与实现改动无关，三组同机实测：
  - T05 时代全量回归（artifacts/rust-tauri/R06/T05/06_workspace_regression/
    full_workspace_final.log）：r04_t08_tool_matrix 全二进制 300.57s（10 tests ok），
    approval_face 即其中 >60s 拖尾者——T05 时代尚无守卫，故通过。
  - 候选 hooks-OFF（诊断性 builder 翻转，已还原）：单跑 300.46s 通过（TEST_TIME_LIMIT_SEC=400）。
  - 候选 hooks-ON（生产默认）：单跑 300.48s 通过（TEST_TIME_LIMIT_SEC=900），
    /tmp/t06_approval_hooks_on_timed.log。
  → hooks 管线增量 ~0.02s（噪声级）；300.00s 默认恰好卡在固有完成线之下。
  同期对照：其余全部测试二进制在 morning full-suite3 与 FIN2 定向重捕间时长比 ~1.0x
  （机器无降速），r00_management_leaves 两轮均 111s——环境正常。

处理（保留守卫 armed，不关守卫硬跑）：
  DEFAULT_TIME_LIMIT_SEC 300 → 600（已知最慢合法用例的 ~2 倍富余；事故现场失控
  为 61 分钟 / 176GB，10 分钟触发仍远在其前）。同步：crate 文档表、
  T06_TEST_GUARD.md §3、DEPENDENCY_DECISIONS.md D-12。守卫自身单元测试引用
  DEFAULT_TIME_LIMIT_SEC 常量，随常量自动成立。

教训记录：守卫阈值必须用"全量二进制逐一实测的最慢合法用例"校准；本次 300s 默认
  依据（"带真实进程/网络腿的二进制也远低于此"）漏测了这一个 ~300s 的合法长跑用例。

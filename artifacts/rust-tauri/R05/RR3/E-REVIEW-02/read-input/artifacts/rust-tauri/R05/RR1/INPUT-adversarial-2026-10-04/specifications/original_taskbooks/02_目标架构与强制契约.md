# 目标架构与强制契约

本文件规定设计边界与可验证语义。具体库版本由 R01 实测锁定。所有建议的组件名称均为目标设计。

## 1. 最终运行拓扑

```text
React 界面 ── DesktopHost ── Tauri 原生窗口/通知/权限
    │                              │ 管理本地自有服务进程
    └──── ServiceClient ───────────┤
CLI / Web / Mobile / LAN ─────────┤
Bridge / cron / 心跳 / 子代理 ────┤ 认证后的命令和订阅
                                 ▼
                   Rust 独立服务 / 组合根
                                 │
       Session/Run Supervisor + Context + ModelGateway
                                 │
                    ToolInvocationGateway
                                 │
            Rust文件/命令工具 / MCP / 受控worker
                                 │
        运行与消息存储 / 现役知识记忆配置库 / 文件资源
```

Tauri 不拥有 Agent 业务执行权；Rust 服务无需 Tauri 也能启动。关闭一个客户端不等于取消所有任务。桌面可以托管自己的本地服务，也可以连接既有远端服务；后者不能启动本地第二内核或结束远端服务。[S04][W01]

最终必须迁入 Rust 的职责：用户任务与尝试状态机、Agent loop、上下文构建/预算/压缩、模型及凭证路由、批准和工具网关、会话与规范化消息、任务调度决策、运行恢复、资源权限和观测关联。外围 worker 可以承担文档解析、浏览器引擎、平台 SDK 编解码等，但不得接收整个用户任务后自行运行另一套 Agent。

## 2. 默认代码布局与依赖方向

```text
rust-toolchain.toml  # 仓库根目录固定工具链，统一核心与桌面
rust/
  Cargo.toml / Cargo.lock
  crates/
    lingxi-protocol/   # wire类型、错误、ID、schema导出；不依赖桌面
    lingxi-kernel/     # 领域规则、运行状态机、上下文及ports
    lingxi-adapters/   # storage/models/tools/integrations各模块
    lingxi-service/    # HTTP/WS、身份边界、配置、进程组合根
    lingxi-cli/        # 保留CLI命令语义，连接同一service
    xtask/            # schema、边界、测试编排与产物检查
  tests/              # Rust集成/契约测试

desktop/src/react/   # 现有界面保留
  .../platform/      # ServiceClient、DesktopHost及宿主适配，位置可按真实结构调整
desktop/src-tauri/   # 单独桌面构建；依赖协议，不嵌入业务内核
workers/            # 仅在确需时建立，或复用现役plugin目录
contracts/generated/# 从Rust协议源生成的schema与TS，不手改
tests/migration/    # 新旧共享夹具及对照测试
artifacts/rust-tauri/# 实施证据，与已有refactor-2026分开
```

若已有同职责目录可复用，在 R01 映射；不得按此树机械复制所有模块。adapter 接口位于 kernel/protocol，service 注入实现。kernel 禁止反向导入 adapter/Tauri。桌面构建与 headless workspace 分开，避免 `cargo test --workspace` 被强迫安装全部 WebView 依赖。无需建立 gRPC、消息队列、微服务或通用分布式事件平台。

默认技术候选为 Rust stable 固定版本、Tokio、axum、reqwest、serde、SQLite、tracing；schemars/jsonschema 用于契约生成校验，rmcp 用于实际 MCP 版本协商。所有候选 API 和 feature 在锁定版本上编译验证，不照抄 `latest` 示例当已实现代码。[W05][W08][W09][W10][W11][W12]

## 3. 身份与权威数据

| 事实 | 权威负责人 | 禁止的替代判断 |
|---|---|---|
| 当前认证主体及权限域 | service认证层＋授权服务 | 模型arguments或前端伪principal |
| 会话身份/分支/消息 | SessionService＋规范化消息存储 | 文件名/时间猜测跨会话归属 |
| 一次用户任务及终态 | RunSupervisor＋运行事务 | provider请求结束、UI流关闭自行判完成 |
| 一次重试 | attempt计数与generation栅栏 | 旧结果覆盖新尝试 |
| 工具是否可用 | ToolRegistry当前generation | 旧目录缓存仍显示即允许 |
| 参数、批准与资源范围 | ToolInvocationGateway | 仅系统提示词提醒“不要越权” |
| 模型/凭证选择 | ModelGateway＋CredentialService | 媒体worker自己找备用key |
| 真实文件与授权 | ResourceService | 模型宣称已生成就创建文件卡 |
| 历史/实时显示语义 | 规范化消息和统一投影 | 各客户端各自清洗MOOD/思考 |
| 用量和因果trace | 唯一modelCall记录 | 按时间接近或事件条数猜测 |
| 调度触发去重 | Scheduler触发收据 | 重启后重新跑全部过期任务 |

ID 采用不透明字符串；保留旧 ID 而非统一重新编号。wire 上的单调序号若可能超过 JS 安全整数，用十进制字符串或证明受限的范围，不允许精度丢失。所有异步结果必须携带并核验 owner/run/attempt/generation。

## 4. 运行状态机

```text
queued → running ↔ waiting_approval
   │         │              │
   └─────────┴──────────────┴→ cancelling → cancelled
             │
             ├→ completed
             ├→ failed
             └→ interrupted / needs_attention（恢复无法安全继续）
```

外部 API 的旧状态名称通过兼容层映射，不强制 UI 改名。terminal status 不再迁回 active。完成状态和交付质量分开：工具完成但没有最终回复不能编造 final；用户已取消但外部副作用是否取消未知，要分别表达。

Run != ModelCall != ToolCall。单次用户任务可以包含多个模型调用和工具调用；各自结束不代表 Run 结束。finalize 只允许一次事务提交，重复请求幂等，冲突结果诊断。每会话状态修改串行，不同会话受全局预算并发；不得持全局互斥锁等待模型/工具网络。

取消分为请求、传播、等待清理、确认结果。迟到事件仅审计，不复活 Run。需要验证进程树的实际退出；仅 drop future/Child 不足以证明结束。[W05] 无法在期限内确认停止时回报具体未知项，不装作一切已取消。

## 5. 工具执行契约

常驻基础工具保持 `read / write / edit / exec_command`。按需目录本身需要的搜索/描述/调用入口继续保留，不得误解成“工具schema总数必须只有4个”。现役 subagent 与实验能力按原开关保留，不恢复强制分发。[S07][S16]

```text
可信入口建立调用上下文
→ target解析与generation
→ schema与资源规范化
→ 权限/安全硬规则
→ 必要时批准
→ 执行前重检撤销/生命周期
→ 记录started意图
→ 单项执行
→ 收据与结构化结果
```

PreparedInvocation 是内核内部不可由模型伪造的句柄/记录；跨 worker 传递时使用短期授权票据并在宿主验证，不把JSON里“approved:true”当授权。批准绑定 target、主体、run、规范化参数摘要、资源、generation、期限及次数。

外部工具 schema 校验与执行 schema 同源，未知 dialect 明确报不兼容，禁止静默宽松放行。真实文件读写须检查最终资源、并发修改和平台路径；shell 的安全边界是授权与操作系统隔离，不能以关键词黑名单代替。

ToolResult 必须区分 success / failed / cancelled / unknown，并含content blocks、resource refs、truncation、error code和重试语义。产物需要存在/类型/权限检查；外发需要真实回执。

## 6. 模型与上下文契约

每个 ModelRequest 固定 principal/run/attempt/modelCall/purpose/provider/model/operation/budget/deadline，凭证在服务端解析。请求快照记录有效配置代次；刷新/撤销用同一代次与存储锁防迟到复活。不同 provider 同名 modelId 不可混用。

内部规范化结构容纳协议差异，不能把必须回传的opaque/signature状态当普通正文，也不能为了统一而丢掉必要字段。具体协议族从现役使用清单推导，不承担“支持所有模型”的无限范围。

上下文输出和观测详情来自同一个 ContextArtifact。静态前缀、动态资料、工具目录和用户来源的边界明确。预算不足时保护系统约束、当前目标、未完成工具对及批准；压缩失败不覆盖原历史。迁移默认不扩大提示词或改变工具策略。

## 7. 事件、历史和重连契约

建议 envelope 最小字段为 schemaVersion/eventId/streamId/seq/sessionId/runId/attempt/eventType/payload；具体可空字段和向后兼容规则在 R01 固定。

关键事件（任务开始/终态、批准决定、工具结果、最终规范化消息）必须可持久恢复。高频文字 delta 可有有界内存缓存与批量检查点，但应明确崩溃时可能丢失的临时尾部，不能声称每个token都持久化。

终态和对应关键事件同事务提交，发布在提交后。快照与后续订阅需要一致cursor边界；重复去重，cursor过旧要求重取快照，慢客户端显式退化或断开，不静默丢关键事件。

实时、重新打开、分页、重连、导出和其他客户端使用同一消息语义。MOOD/思考标签兼容解析只有一个权威入口。无final的工具卡也必须可展开。

## 8. 存储、迁移与回滚契约

最终新内核运行/规范化消息存储由Rust拥有；现有知识、记忆、配置、附件等先保护原格式。R01必须落实一份具体存储ADR，不能同时保留两个消息权威。

默认新运行/消息库配合只读旧JSONL导入：原始记录保留，转换写新隔离库，验证成功后按会话/整目录的明确切换点启用新权威。旧未知字段、缺失关联、签名块分别归档/保留，不猜测成新运行事实。

单写者不能只靠新程序自觉：必须用旧版本实际理解的epoch拒写，或可验证的分离数据根与活动目录机制。不能假设旧程序认识新增锁文件。备份采用SQLite可用备份机制/停写快照；多库和文件之间必须有共同静止点。[W06][W07]

外部副作用和本地数据库没有天然跨系统事务。started但无回执的操作恢复为unknown；只在已有幂等key/状态核验支持时自动重试。重启不能重新运行全部工具。

回滚前保护新版本新增会话、文件和配置。恢复旧备份只能恢复旧时点，不能称无损。新数据可以导出归档并在再次前滚时幂等合并；无法在旧版继续编辑的内容须明确告知。

## 9. 宿主与远端安全契约

Tauri capability限制的是前端调用宿主，不代替Agent授权或OS沙盒；自定义命令也必须明确纳入权限限制，多capability叠加后的实际权限需验证。[W02]

外部网页、文档HTML/SVG和工具输出不与主界面共享可信native权限。前端不暴露任意shell，sidecar固定二进制及受限参数。原生服务token不放URL/预览内容。

远端服务的执行节点必须显式：服务端文件/命令/浏览器默认在服务节点；客户端采集屏幕/麦克风需独立授权。远端能力不足不得偷偷fallback到用户本机执行。

## 10. 最终“不算完成”的情况

Rust service只转发整任务给Pi；新代码存在但真实入口仍走旧逻辑；只有聊天和read通过，其他现役功能被隐藏；Tauri仍依赖Electron打印或浏览器；取消只改状态；实时/历史解析两套；新旧同时写同一库；回滚删新数据；只跑Linux单测就称四平台通过；没有真实凭证/安装产物却写已验证；清退后复用旧SHA测试结果。

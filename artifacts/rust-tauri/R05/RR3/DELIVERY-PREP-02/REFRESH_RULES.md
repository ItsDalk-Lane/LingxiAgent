# 最小交付刷新规则

本轮规则只解释 DELIVERY-PREP-01 的既有清点，不能把本轮名单直接当最终暂存输入。本轮没有执行此处描述的后续 Git 写操作。

1. **先实际枚举，再分类。** 等 J/G/E/FINAL 的对应作者停止写入后，在全新交付清点目录只读运行 `git ls-files --others --exclude-standard -z`、`git diff --name-only -z` 和 `git diff --cached --name-only -z`。只取 RR3 和本轮已授权改动，记录真实 HEAD、分支、UTC、退出码、文件类型/大小/mtime。目录或符号链接先单列，不递归导入嵌套仓库，不解析仓库外链接。新文件、新轮次、变动文件必须重新实际判断，不能沿用旧条目的 hash 或 PASS。
2. **以实际 driver 的读写位置为准。** 原始报告、历史 FAIL、真实命令/退出/日志、原始测量序列、独立驱动、变异/恢复说明、来源摘要通常纳入。对源码/配置留样，证明它是独立保存的原文或恢复基线，列出创建源、读取者、变异目标及历史/current hash；只有证据文本角色，不能成为产品/测试入口。全量或小型可运行故障工作副本、实验仓库、缓存和运行状态仅本地保留。目录名 `snapshot`、`pristine`、`copy` 和扩展名都不能单独决定。
3. **保持本轮已证明的边界。** A-REVIEW-01/snapshot、A-REVIEW-02/snapshot、I-REVIEW-01/old-independent-copy 是工作副本，含其中复制文档/配置；恢复相等也不改变归属。A-02/snapshot 的三个正常脚本是被单独保存并只读消费的源输入，故障写在另一目录。负测的 EV/pristine、恢复回归的 pristine/runner-pristine 是 COPY 之外的独立基线；逐文件确认与该轮基线相等。snapshot-cmp-failure 需同时证明 cp 产物字节等于基线、失败只是检查命令返回异常，不能因目录有 fail 就排除，也不能把失败腿记成功。E 的 source-input 和 TRIAGE 的逐文件读取摘存按其读取索引确认；来自外部实验副本的定向摘存不自动等于整个实验副本。
4. **运行令牌与用户内容不交付原文。** 新鲜合成 home 仍会生成真实可使用的临时票据或凭证。一次性发钥匙响应、ws-ticket 响应、token 文件、设备凭证、数据库及运行 home 原件 localOnly；仅存 SHA/size、合成来源、生成 driver 和必要不含值的摘要。真实用户配置复制件或无法证明归属的材料也先排除拟交付并具体注明来源缺口，不能输出秘密原文或把未知写成安全通过。源码中明确的合成负例常量及测试日志不能仅因 `secret` 字样删除。遇到混有敏感值的日志，保留本地原件，用另存的必要摘要说明边界，不改历史文件。不要把 `home-before.json` 这样的摘要文件仅因名字前缀当作实际 home 内容；需辨清 driver。（本轮未扩大复审 PREP01 的全部既有运行状态分类。）
5. **排除与原证引用同时存在。** 不修改旧 manifest 消除引用。每项新排除原件登记 originalPath、实际内容 SHA256、字节、来源/driver、localOnly=true、remoteOriginalAvailable=false；旧原件可在 size/mtime 与已验证身份相符时明确继承 PREP01 hash。缓存无需批量重新读字节；继承的历史缓存 hash 必须标明是历史声明而非本轮重哈希。引用处可链接新的边界索引，不能称被排除原件已远端可取。可复现方法不保证得到同字节历史 binary。
6. **合成精确列表并核对。** 检查每个实际候选唯一覆盖、include/local/unknown 无交集、数量/字节总和一致；JSON 可解析且无重复键；新报告/规则/driver 引用存在；新材料自身清单 hash 可重算。凡发生内容变化须重新计算绑定并复核来源。正式报告/原日志/测量序列不能因失败而清理。对必要但只在本机的依赖明确写本地读取边界，不能把引用存在等同于交付闭合。
7. **最后交给已有授权的交付操作者。** 本轮只提供可审阅清单，没有 stage/commit/push 权限动作。最终仍须精确到文件，不整目录 `git add`，不混缓存、故障副本或用户内容；提交/推送后的远端事实另取真实回执。大于普通 GitHub 单文件限制的历史 rlib 及实际 binary 维持 localOnly；若用户明确要求远端必须取到原件，列明未满足的具体项，另解决渠道，不自行引入 LFS/外部存储/发布。

机器判定及每条规则对应的现有证据见 [classification-rules.json](classification-rules.json)。本轮 768 条复核器见 [classify.py](classify.py)，它**只重算旧清点对象**，故不是自动发现或自动批准将来新增路径的程序。

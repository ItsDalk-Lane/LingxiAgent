## 4. 逐项执行规格

### R05-T01｜统一ModelGateway与能力矩阵

**做什么：**每次调用都能回答使用哪个模型、凭证和目的。

**怎么做：**

1. 从 ModelManager、model-operation-resolver、llm-client、媒体适配与 Pi 适配收集实际协议/目的/能力，而非枚举市场全部模型。
2. 定义模型标识 provider+model+operation、输入输出模态、工具/推理支持、上下文预算及协议选项；同名 modelId 不能跨 provider 混用。
3. 主对话、标题、摘要、记忆、审批、视觉、embedding与媒体均由同一 Rust Gateway解析身份、策略和观测。
4. 不支持的能力在请求前明确报错；供应商特有字段保存在受控扩展区，不能被公共转换静默丢失。

**必须交付：**ModelGateway；PROVIDER_SUPPORT_MATRIX.json；操作到模型映射。

**验收：**

#### R05-A01｜同名模型不串凭证

前置：两个 provider 注册相同 modelId。

操作：指定其中一个 provider 调用。

通过条件：只使用对应 endpoint/凭证/trace 标签。

证据：协议替身断言。

环境：本机隔离环境；外部协议使用确定性替身。

#### R05-A02｜不支持能力提前失败

前置：模型未声明工具或图像输入能力。

操作：提交对应请求。

通过条件：明确配置错误，不发送损坏请求或偷偷换模型。

证据：请求计数与错误结果。

环境：本机隔离环境；外部协议使用确定性替身。

**禁止替代：**不得以占位实现、跳过断言或仅更新完成状态替代真实实现。

### R05-T02｜凭证所有权与并发刷新

**做什么：**刷新和重试不会形成多条隐式凭证链。

**怎么做：**

1. 迁移现役 API key/OAuth 登录/设备授权/刷新形态；秘密仅在服务侧，前端拿到状态而非明文完整凭证。
2. 按 provider 做并发刷新合并与原子写入，读写使用同一存储锁；删除/撤销后阻止旧刷新结果复活凭证。
3. 明确优先级及缺凭证错误；禁止失败后悄悄回退到其他 provider或环境变量秘密。
4. OAuth回调校验 state/来源/过期/PKCE等实际协议要求；不虚构尚未验证的供应商登录方式。
5. 凭证迁移保留权限模式和脱敏；日志/导出/崩溃报告扫描秘密。

**必须交付：**CredentialService；OAuth适配；刷新与撤销状态机。

**验收：**

#### R05-A03｜并发401只协调一次刷新

前置：同 provider 多个请求同时收到401。

操作：触发刷新与重试。

通过条件：刷新按锁合并，重试受限且无跨provider fallback。

证据：刷新计数及请求轨迹。

环境：本机隔离环境；外部协议使用确定性替身。

#### R05-A04｜撤销后迟到刷新不能复活

前置：刷新尚未完成时用户删除凭证。

操作：刷新随后返回新 token。

通过条件：新 token 不写回生效，不继续原请求。

证据：撤销竞态断言。

环境：本机隔离环境；外部协议使用确定性替身。

**禁止替代：**不得以占位实现、跳过断言或仅更新完成状态替代真实实现。

### R05-T03｜实现实际使用的文本协议

**做什么：**兼容的是具体协议，而不是包名。

**怎么做：**

1. 按 R00 矩阵逐一实现 OpenAI兼容聊天/Responses、Anthropic风格、OAuth专有或其他实际在用协议；不存在的协议不扩范围。
2. 用脱敏 golden 验证角色、工具声明、tool_call_id、工具结果、停止原因、系统消息、缓存/推理参数和多模态引用。
3. 模型结果还原为规范化内部类型，同时保存重放必需但不可展示的协议状态；禁止把未知 provider 块直接塞正文。
4. 每个协议同时测试流式、非流式、错误、截断、无usage、未知字段和兼容端点差异。
5. 迁移完成的 provider 路径不得再调用 Pi 的 model runtime/complete/stream，允许保留旧路径作隔离对照。

**必须交付：**Rust provider adapters；协议golden测试；供应商兼容说明。

**验收：**

通过条件：发送正确关联的tool result，无ID丢失/角色错误。

证据：原始请求与规范化输出对照。

环境：本机隔离环境；外部协议使用确定性替身。

环境：本机隔离环境；外部协议使用确定性替身。

### R05-T04｜流式解析与消息阶段规范化

**做什么：**分片不等于完整语义或完整工具参数。

**怎么做：**

1. 实现增量字节/SSE/相应协议解析，覆盖 UTF-8跨片、CRLF、多个帧一片、单帧多片、工具参数增量和嵌套内容块。
2. 只有完整且符合schema的工具调用才能进入网关；结束前不执行半截 JSON。
3. 将 reasoning/commentary/final/toolcall/usage 与协议结束事件区分；未明确阶段按冻结策略等待或标未决，不即时当final。
4. MOOD/think兼容解析集中在明确边界；同样输入生成同样规范化段，前端不再自己补清洗。
5. 限制帧/参数/缓冲总大小；断流记录 partial与原因，不以连接关闭自动成功。

**必须交付：**StreamDecoder；CanonicalMessageNormalizer；流式边界夹具。

**验收：**

#### R05-A07｜任意分片保持语义

前置：同一协议响应按每字节及随机片段切分。

操作：分别解析执行。

通过条件：规范化结果一致，工具只执行一次且参数完整。

证据：分片属性测试。

环境：本机隔离环境；外部协议使用确定性替身。

#### R05-A08｜中断流不伪造最终回复

前置：流只输出过程/工具参数后断开。

操作：结束请求并恢复会话。

通过条件：显示partial/失败或中断，不生成假的final_answer。

证据：断流和历史一致性测试。

环境：本机隔离环境；外部协议使用确定性替身。

**禁止替代：**不得以占位实现、跳过断言或仅更新完成状态替代真实实现。

### R05-T05｜网络策略、超时与安全重试

**做什么：**对无法确认是否已接受的请求采取保守处理。

**怎么做：**

1. 统一系统代理/手动代理/直连、localhost bypass、企业根证书与每provider endpoint；不得通过关闭证书验证排障。
2. 设置连接、首字节、空闲流、总预算与重试上限；取消要关闭读取与相关请求句柄。
3. 区分尚未发送、已发送未回应、已部分输出、已触发工具四阶段；重试规则按协议与操作幂等性定义。
4. 对429尊重可用的重试提示并受总预算约束；认证刷新不允许形成无限循环。
5. 涉及远端图像/文件拉取的网络策略与凭证作用域独立验证，防止把私密凭证发往任意地址。

**必须交付：**网络执行策略；超时/重试状态表；代理与证书测试。

**验收：**

操作：取消任务。

通过条件：读取停止、连接回收、后续片段不写正文。

证据：网络探针与任务状态。

环境：本机隔离环境；外部协议使用确定性替身。

证据：外部请求计数。

环境：本机隔离环境；外部协议使用确定性替身。

### R05-T06｜多模态及辅助调用接线

**做什么：**不能只有主对话完成Rust迁移。

**怎么做：**

1. 按当前配置入口保留图像/视频/语音输入输出能力及默认参数，辅助槽位映射到同一Gateway。
2. 编码/解码允许委托受控worker，但模型选择、凭证、请求生命周期、用量与取消由Rust持有。
3. 大附件使用ResourceRef及受控流，不把所有二进制base64复制进每条事件；限制大小和缓存。
4. 验证文本主模型调用不同provider媒体模型、视觉桥与语音操作时，不串供应商凭证和消息阶段。

**必须交付：**多模态/辅助操作接口；ResourceRef传输；媒体调用契约测试。

**验收：**

### R05-T07｜用量观测与因果关联

**做什么：**多轮轨迹结构和计费统计不能随重写退化。

**怎么做：**

1. 保留用户会话多轮观测复用规则，单次请求是独立modelCall但归属同一会话trace；后台独立根按既有语义。
2. 保存purpose、run、attempt、parentCall、provider、model、输入/输出token、缓存/推理usage、耗时与状态；未知值用未知而不是零。
3. 最终usage按唯一请求结算并去重；不能把重传事件或工具内部调用重复累加。
4. 保留按日期/类别/模型/会话筛选、请求详情与导出所需字段和隐私设置；在R07/R08验证现役UI链路。

**必须交付：**Trace/UsageCollector；兼容查询结构；观测去重测试。

**验收：**

## 5. 本阶段验证方式

逐场景执行并登记命令/预期/实际/退出码/SHA/环境/日志；相关基线回归和平台要求按[05验收协议](05_验收与性能协议.md)运行。新工具或脚本未创建前不能写成已经运行成功。

各任务的场景是最小基础：从R00功能/入口/存储清单展开适用组合，特别是身份、权限、副作用与数据迁移；不能用两个样例推定全部入口安全。外部服务替身与真正内核组件的边界必须写清。

## 6. 阶段放行条件

全部现役协议有确定性契约覆盖；Rust主循环不再调用Pi；四工具真实闭环及失败恢复通过。真实供应商/凭证验证结果单列，未通过项最迟R10阻断发布。

未满足必需项则标FAIL/BLOCKED；完成实现但尚未独立复核标READY_FOR_REVIEW。不得仅统计绿色测试数量。发布授权条件项独立处理，未授权不伪造其结果。

## 7. 失败与回退

停用Rust预览Provider入口，保留隔离凭证副本并按权限清理测试秘密；旧生产入口仍不切换。

回退范围只能包括本次获准修改；保留原始失败证据和用户已有数据。关键问题按根因修复同类路径并重跑受影响整组，不能另建绕过分支。

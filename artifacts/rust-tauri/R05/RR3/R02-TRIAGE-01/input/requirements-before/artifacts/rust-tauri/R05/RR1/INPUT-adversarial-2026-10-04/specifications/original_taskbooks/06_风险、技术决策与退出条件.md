# 风险、技术决策与退出条件

风险账本不是延后交付的借口。每一项都有明确责任阶段；出现不可满足条件时停止相关替换，不擅自减少产品能力。

| 风险 | 早期证明/实现归属 | 必须检查的失败窗口 | 放行/退出条件 |
|---|---|---|---|
| 浏览器可见交互丢失 | R01-T04；R07浏览器；R09 | 登录、cookie隔离、用户接管、截图/下载、tab/会话恢复 | 原生样例和四平台行为通过后才能删旧宿主；不可用headless替代可见功能 |
| PDF排版/字体失真 | R01-T05；R07办公；R09 | 字体未加载、跨页表格、图片、页尺寸、外部资源 | 固定样本的内容与视觉都达标，正确性不足时保留旧方案作隔离过渡但不宣称迁移完成 |
| Pi隐藏行为缺漏 | R00-T03；R05/R06；R11-T01 | compaction、会话分支、认证、特殊流块 | 每个实际能力有新实现/等价测试，旧Pi无法再从生产内核路径被加载 |
| 旧二进制绕开新锁 | R02；R08-T05 | Rust单写者锁对旧Node无效、旧版本自动启动 | 真实旧安装包反向启动不能写新数据；可兼容epoch或物理隔离，不能仅有新互斥锁 |
| 副作用重复执行 | R03/R04/R05/R07 | 外部完成与本地收据间崩溃 | 不确定态、外部幂等键/核验或用户确认；不能承诺全局exactly-once |
| 取消名存实亡 | R03；R04-T05；R09 | model/tool/PTY退出延迟，孤儿孙进程 | 实际进程与管道收敛，无关哨兵存活，超时真实暴露 |
| 凭证/主体混用 | R04/R05/R07 | OAuth刷新并发、撤销、跨agent/remote请求 | 每条入口身份由可信层生成，所有模型调用统一解析，不允许私有fallback凭证链 |
| Node worker变成第二内核 | R00/R01/R07/R11 | worker自行读全量home、自己调模型循环、决定批准 | 剩余worker只承担明确单次外围能力；不拥有Run/Session终态/批准 |
| 新旧数据格式互相污染 | R06/R08/R11 | JSONL+DB双权威、迁移中断、未知块丢弃 | 原始资料保留、收据与校验完备、切换原子、回滚保留新增数据 |
| 原生平台差异被遗漏 | R01/R04/R09/R10 | Windows Job/UNC、macOS权限、Linux WebKit/依赖 | 四架构真实产物测试，环境不足列BLOCKED而非悄悄缩小支持面 |
| 更新链锁死旧用户 | R09/R11-T04 | Electron更新器不能安装Tauri产物、协议/数据不匹配 | 独立过渡安装/可验证升级路径，不把新格式伪装成旧更新包；失败保留可启动版本 |
| 体积收益被外置浏览器抵消 | R00/R01/R10 | 仅统计主程序、首次下载不计入 | 完整必需依赖+首次使用成本纳入，与事前目标一致 |
| 无限修复循环 | R00账本；R10审阅；R11终验 | 每轮只修最新一个点、范围不断增加 | 冻结完整矩阵，按缺陷根因簇修复并重跑关联整组；新增真缺陷不能忽略，但不得无理由扩大产品范围 |
| 真实账户/签名缺失 | R05/R07/R10/R11 | 替身通过被写成live通过、unsigned冒称正式发布 | 区分技术功能/真实业务/签名/发布授权；缺项明确阻塞对应gate |

## 1. 技术决策格式

每个ADR包含：问题与用户目标、基线证据、不可违反契约、候选及实际验证、选择与理由、依赖版本、性能/安全/兼容影响、退出条件、受影响任务/测试。

允许执行者按源码做局部实现选择；不允许在未做实验时写“某库理论可行”，也不允许为了纯Rust目标自造浏览器、Office格式引擎或整个MCP协议栈。

## 2. 未知事项的处理

能从源码、测试、配置或官方文档确定的事项由执行者调查。存在多种等价实现时选择最小、易验证且符合契约的一种并记录。涉及删除功能、扩大权限、迁移真实数据、费用/外发、远程写入、正式发布则没有默认授权；可以完成所有不依赖该授权的隔离实现与验证，不能把未授权的操作假写成已经完成。

## 3. 最终必须明确回答

Rust是否拥有真正Agent循环与所有核心状态？Tauri是否仍依赖Electron运行？生产必需的Node/Python/浏览器程序具体做什么？所有原有入口是否可达？旧数据和迁移后新增数据能否恢复？四平台真实安装包是否可用？哪些性能收益确实测得？哪些事情没有验证？

任何一个问题都不能用“总体完成95%”替代逐项事实。

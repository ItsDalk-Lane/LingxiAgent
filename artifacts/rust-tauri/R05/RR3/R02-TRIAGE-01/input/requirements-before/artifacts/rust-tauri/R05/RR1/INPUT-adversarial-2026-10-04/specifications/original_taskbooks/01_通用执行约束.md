# 通用执行约束

适用于 R00—R11。本文与对应阶段任务书必须同时阅读。这里的“必须”是本次迁移的验收要求，不是对当前代码已满足要求的声明。

## 1. 本轮授权与范围

本包是可执行任务规格，不是代码实现或测试报告。编制阶段未修改仓库、未提交代码、未创建分支/PR、未运行项目测试、未迁移用户数据。所有任务和验收场景初始为 NOT_STARTED。研究基线见总入口；实施以真实工作区 HEAD 为执行基线并说明差异。

用户选择的路线：Rust 重写整个 Agent 内核，Tauri 替代 Electron 桌面宿主，保留 React/TypeScript/Vite 前端及已采纳产品功能。不是 Rust 包装旧 Pi Agent，也不是所有第三方工具都必须使用 Rust。

默认一次只执行用户明确指定的阶段。拿到整包不构成执行后续所有阶段、远程 push、创建 PR/tag、发布、付费请求、向真实联系人发消息或迁移真实数据的授权。测试代码和临时夹具可在本阶段范围内创建；需要外部副作用时先完成离线验证，列出精确阻塞，不能谎报通过。

不覆盖用户未提交修改。不使用 reset --hard、clean -fd 或删除用户数据来获得“干净测试”。清理自己创建的临时测试资源必须记录范围。

## 2. 现役行为和排除项

先读现有功能与排除矩阵 [S16]，然后从实际生产入口复核。源码有目录并不证明功能正在使用，历史文档中“完成”也不证明当前版本所有路径仍然通过。

硬排除：已撤回的专用子代理目录/强制分发改造、独立知识研究引擎、本地模型管理子系统。现役 subagent、相关实验开关、现役知识库、Ollama 模型接入不是上述撤回功能，必须保留。用户自装 MCP/插件不是仓库内置能力；用合成实例测试协议边界，真实实例只在授权范围使用。

不新增功能，不重做布局，不更换人格设计，不扩成微服务，不为“更先进”引入另一套工作流引擎。必要的迁移/版本错误提示和权限适配属于迁移范围，但必须保护现有交互。

## 3. 文档优先级与合理决策

优先级：用户当前明确要求 > 本包通用约束/目标契约 > 本阶段任务书 > 实施 ADR > 历史任务书/注释。遇到安全、真实数据、范围冲突必须停在该项并报告事实；不得任意扩大或缩减范围。

执行模型可以根据真实源码调整文件位置和具体库版本，不能机械照抄过时行号。调整方式：记录发现→现有调用链→候选方案→兼容/安全/性能影响→选择理由→需要变化的测试。仅改变实现细节且不改变契约可写 ADR 后推进；改变产品功能、支持平台、权限范围或数据回滚保证必须得到明确决策。

本包列出的 `rust/`、`DesktopHost`、`ModelGateway` 等是拟建立的目标路径/组件，不是声称当前仓库已有这些 API。执行时先查真实实现；同职责已存在的边界复用或迁移，不再叠加一层重复 manager。

## 4. 每项任务固定执行顺序

1. 读取本任务、对应源文件、调用方、真实注册入口、持久化方与现有测试；记录“观察事实”和“设计决定”，不混写。
2. 为本任务两个基础场景及矩阵扩展建立可重现输入和预期。能先写失败测试时先写；外部响应可替身，但不能 mock 掉本任务要证明的网关/调度/存储。
3. 实现最小闭合改动，包括错误、取消、清理、配置、旧数据和平台适配；禁止只新增文件而不接生产链。
4. 运行针对测试，检查真实副作用、持久化和用户可见结果；编译成功不代表任务完成。
5. 更新需求→实现→测试→证据映射，运行对应阶段门禁；失败按根因处理，不能改预期掩盖错误。
6. 记录修改范围、剩余风险和下一项输入。涉及公共契约变更时重测全部消费者，不只本文件。

阶段内默认顺序执行 T01→T02→…；具备独立文件与清晰契约后可以并行无副作用测试。不要让两个执行者同时写同一份源码、运行库、配置或迁移目录。阶段间并行不是默认授权。

## 5. 测试有效性

测试分层：纯状态/算法、协议契约、真实服务集成、真实文件/进程、真实桌面安装包、已授权外部服务。每个测试写明自己属于哪层。mock Provider HTTP 是有效协议测试，但不是真实供应商验收；mock Tauri IPC 是有效组件测试，但不是 OS 权限证明。[S17][W03]

禁止：删除仍保护真实行为的测试、把断言改成永真、catch 错误后返回成功、将 skipped/ignored 当通过、仅凭函数名存在证明接线、仅凭测试文件存在证明运行通过。为平台例外给出明确理由，不能把所有 macOS/Windows 测试排除后说跨平台完成。

允许合并重复测试或移除已退场的私有实现测试，但必须保留对应公开行为/兼容迁移的保护。每次改动只重跑受影响层和必要门禁；最终候选必须绑定最终 SHA 重跑关键全链。

## 6. 证据状态与放行

场景状态：NOT_STARTED、IN_PROGRESS、PASS、FAIL、BLOCKED、STALE、NOT_APPLICABLE。PASS 必须含命令/测试ID、预期、实际结果、tested SHA、环境、退出码、证据路径/摘要。NOT_APPLICABLE 仅用于本来不适用的矩阵组合，不能用于删除必需功能；需具体理由及审阅者记录。

阶段状态：NOT_STARTED、IN_PROGRESS、READY_FOR_REVIEW、ACCEPTED、BLOCKED。实施者填 READY_FOR_REVIEW，不自行假冒独立审阅者；用户/指定审阅者基于证据决定 ACCEPTED。阶段报告可说明“离线实现完成，真实环境尚阻塞”，但不得把对应场景写成 PASS。

R01 的其他平台原型、R05 的真实模型等有明确后续截止关卡。它们可以作为下一阶段的未关闭交接风险，但需满足当前阶段本机/确定性门禁，且不得越过 R10 的最终必需关卡。对应阶段特有门禁更严格时从其规定。

技术验收、发布授权、实际发布、真实数据迁移四个状态独立。技术通过不意味着已经发布；发布授权不意味着可以读取或迁移个人数据。

## 7. 修改后测试结果过期规则

每项结果固定 tested SHA、工具链、lockfile、配置、fixture 与产物 hash。上述任一项变化时先评估影响范围；受影响结果标 STALE。跨语言协议、权限、存储、构建、共享前端等公共变动触发所有受影响消费者回归。

R11 删除旧代码以后必须重新生成最终证据，不能把 R10 旧 SHA 的报告复制为最终结果。未改动模块的旧单测可以作为辅助证据，但不代替最终安装/集成关卡。

## 8. 数据与秘密

研发及迁移演练使用独立目录和脱敏副本。启动脚本可能覆盖 LINGXI_HOME，必须检查实际生效值，而不是相信调用前环境变量。[S04]

秘密只存服务端受控存储，禁止写仓库、fixture、截图、日志、导出和交付包。测试签名 key 不得当正式发布 key。真实附件和数据库不能整包上传到公开仓库；证据使用合成数据、哈希与最小脱敏片段。

旧库备份注意 WAL 和多库/文件的一致点，不能只复制活跃 `.db` 主文件。[W06][W07] 不允许旧 Node 和新 Rust 同时作为相同权威数据的写者。未知外部副作用不盲目重试。

## 9. 实施与验收停止条件

单任务停止：其场景与矩阵扩展通过、真实接线完成、必要回归通过、证据齐备。阶段停止：全部任务完成且阶段门禁满足，输出交接，等待明确下一阶段授权。整轮停止：R11最终契约全部满足，未授权发布则停在候选交付，不继续顺手优化。

本包的 200 个基础场景用于把关键链路前置，不是“200 个测试可以证明永远无缺陷”的承诺。新增真实入口/反例必须进入既定矩阵；不能无限扩大产品需求，也不能隐瞒必要缺口。

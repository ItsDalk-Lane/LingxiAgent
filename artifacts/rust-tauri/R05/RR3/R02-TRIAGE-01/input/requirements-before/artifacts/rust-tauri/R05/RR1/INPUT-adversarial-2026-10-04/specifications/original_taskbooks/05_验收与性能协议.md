# 验收与性能协议

本文件定义执行端必须落实的验证方法，不是已经发生的测试记录。200个场景是本包的基础规格；R00必须按实际叶子功能补齐，不得把“已跑200个”当作所有功能已经覆盖。

## 1. 四层证据与可接受替身

| 层次 | 必须验证的对象 | 允许替代 | 不允许替代 |
|---|---|---|---|
| 纯逻辑/性质 | 状态迁移、身份、参数规范化、预算、投影 | Clock、随机源、外部输入 | 把待测算法mock掉 |
| 契约/服务集成 | 实际Rust service、Gateway、Supervisor、存储、认证和各入口 | 供应商/MCP/Bridge外部协议服务器 | 绕过路由直接写出预期状态 |
| 宿主/平台 | 真实PTY、进程树、路径/沙盒、Tauri WebView、系统权限 | 临时目录、受控网络端点 | 用普通浏览器mock证明原生功能 |
| 真实业务/产物 | 真实provider/账户必要冒烟、旧数据副本、安装升级、浏览器/PDF | 脱敏账户和用户明确授权的数据副本 | 以源代码存在或开发机启动代替安装包验证 |

实际模型文本不是稳定oracle。协议层用确定性替身控制输入；真实模型行为评估按工具目标、参数、权限和结果判定，不要求最终文本逐字一致。外部调用未授权时只运行替身，LIVE场景保持BLOCKED。

关键链必须做到：输入来自真正入口，状态由真正owner产生，工具结果由真正执行器或明确的外部替身返回，历史由真正存储读取。不能用测试脚本预先写入“成功”再验证界面显示成功。

## 2. 已有验证命令：先核对当前仓库，再执行

下列命令在研究基线的package/CI中存在；实施HEAD变化时R00重新检查。Node版本与构建原生helper遵循当前CI，不直接照旧版本升级依赖。[S01/S17/S18]

```bash
npm run typecheck
npm run typecheck:core-contracts
npm run check:dependency-boundaries
npm run check:tool-invocation-boundaries
npm run lint
npm run build:renderer
npm run test:knowledge-platform-smoke
npm test
```

先跑受影响测试，再跑阶段要求的类型、构建和回归；未修改且已有同一SHA/环境证据的检查不无理由重复。新改动影响其输入时证据过期，必须重跑。旧测试如果只锁私有实现，可迁入公开契约；安全、旧数据与发布测试不能靠删除消除失败。

## 3. 新Rust验证接口：这些是待建立的约定，不是现成脚本

R02建立`rust/Cargo.toml`后，以下标准Cargo命令才适用；manifest若按获准ADR改名，统一更新本包对应命令索引，不能留下两套入口。

```bash
cargo fmt --manifest-path rust/Cargo.toml --all -- --check
cargo clippy --manifest-path rust/Cargo.toml --workspace --all-targets --locked -- -D warnings
cargo test --manifest-path rust/Cargo.toml --workspace --locked
```

R02还需实现`xtask`的实际子命令及`--help`。建议接口如下；不存在或测试集合为空时必须非零退出，不可用一个总是成功的包装脚本满足任务：

```text
cargo run --manifest-path rust/Cargo.toml -p xtask -- check-contracts
cargo run --manifest-path rust/Cargo.toml -p xtask -- check-boundaries
cargo run --manifest-path rust/Cargo.toml -p xtask -- verify-stage R03 --evidence artifacts/rust-tauri/R03
```

`verify-stage`读取实施验收映射并执行登记的测试/校验命令，收集真实退出码、平台、SHA及日志。不能仅统计JSON中的PASS。其输入schema、场景→测试映射、空集合检查、超时和结果版本必须有负向测试。

Tauri独立manifest的fmt/clippy/build/E2E及安装包命令由R09按锁定工具链登记；先验证纯Rust服务可在没有WebView系统依赖的环境构建，再验证桌面。安装包测试不得默认依赖仓库node_modules或开发机PATH。

## 4. 必须展开的验收矩阵

**入口×权限×工具生命周期。**从R00真实入口清单出发，覆盖直接/按需/MCP/插件/开发/子代理/后台适用路径；至少允许、拒绝、需审批、批准后改参、目标禁用/卸载、目录陈旧、取消、调用者伪造。安全高风险组合必须逐条覆盖，不能仅用pairwise推断其余安全。

**模型×协议×请求状态。**只覆盖现役支持范围，但每种实际协议必须包含流/非流、工具参数分片、多个工具调用、结束原因、空结果、断流、超时、取消、认证刷新、429/5xx及供应商特殊块。不同模型/供应商同名、输入输出模态及辅助调用不可串凭证。由R05支持矩阵标出不适用组合及依据。

**资源×身份×数据版本。**覆盖跨agent/session拒绝、附件跨页、历史fork、checkpoint/rewind、旧JSONL未知字段、provider opaque块/签名块、文件丢失、损坏尾行、读写冲突、符号链接/junction、磁盘满、迁移中断、旧二进制写入和迁移后新增数据回滚。

**取消×发生时点。**提交前、排队、请求中、参数未完整、等待审批、工具执行中、外部成功后本地未落盘、终态后迟到事件。每例断言用户状态、内部owner、实际子进程/外部副作用、持久化记录与恢复行为。

**平台×真实产物。**保留研究基线的macOS arm64、macOS x64、Windows x64、Linux x64四组。R00冻结实际支持的最低系统/WebView要求，runner可用名称变化不等于取消架构支持。[S18]

Tauri当前官方文档列有跨平台WebdriverIO服务方案；实施时应针对锁定版本验证真实原生驱动。浏览器模拟、传统tauri-driver和嵌入式测试驱动的能力边界分别记录，测试插件不得进生产包。[W03]

## 5. 必须为零的正确性回归

以下任一真实失败阻止相关阶段放行：未批准的敏感副作用、身份/凭证/资源串用、用户数据不可恢复丢失、同run重复终态提交、取消后旧结果污染新attempt、旧新进程双写同一权威数据、未知外部结果被盲目重试、worker绕过授权、安装包缺关键依赖。

“必须为零”是测试门槛，不是对所有未知输入绝无缺陷的保证。发现用例之外的真实失败同样要纳入阻塞账本，不能因不在200场景中就忽略。

## 6. 性能测试与提前冻结的数值门槛

### 6.1 测量条件

R00保存硬件/OS/电源模式、数据规模、commit、构建模式、测量工具版本、工作负载与原始数据。比较三组：旧Electron+Node、旧Electron+Rust、Tauri+Rust。辅助浏览器、文档renderer、worker、外置索引等所有必需进程均计入；共享内存是否去重及采用RSS/PSS等哪个口径必须固定，不能跨平台混算。[W04用于进程模型背景]

每项启动/请求/历史加载至少30次独立样本，报告n、median、p95、最小最大与离散程度；本地/供应商网络阶段分别计时。冷启动是本协议定义的应用冷启动，不声称清除了操作系统所有缓存；warm定义也明确写入。性能测试使用发布优化构建，禁止一边debug一边release比较。

最低负载：空闲、短会话、1000条消息的长会话、持续流式输出、多个会话并发、PTY大输出、浏览器多实例及PDF转换。具体字节/附件/并发数由旧系统能力与受控夹具决定并冻结，不在得到结果后缩小负载。

### 6.2 默认建议值与生效规则

下面是设计门槛建议，不是本次实测数据或收益保证。R00必须在出现Rust测量结果前将各平台的实际数字写入`PERFORMANCE_THRESHOLDS.json`并附理由；可因测量噪声/硬件能力作事前调整，之后修改需要独立变更记录，不能为了通过测试放宽。

| 指标 | 建议起始门槛 | 测量边界 |
|---|---|---|
| 受控本地取消受理 | p95 ≤ 250ms | service收到取消到持久化cancel_requested/返回确认，不等同外部操作已撤销 |
| 受控进程树清理 | 正常终止窗口≤3s，强制终止后总计≤5s | 含等待退出/回收，哨兵不得被杀；平台无法证明清理则报告失败 |
| 本地业务处理/历史读取 | p95不劣于基线10%以上 | 噪声容限提前量化，网络/模型等待分开 |
| 提示词/固定工具开销 | 不高于旧同任务固定前缀，除已批准增量 | tokenizer、语言和功能开关相同；不得删除必要能力换分数 |
| 长时资源增长 | 2小时或1000次受控任务后，无未清理任务/FD/子进程持续单调增长 | 执行端真实运行，记录采样；缓存有固定上限与淘汰证据 |
| 迁移收益 | 至少一个R00选定的目标指标改善超过噪声界限 | 可以是启动、总内存或分发/安装占用；其他关键指标满足回归门槛 |

最终没有证明改善时，诚实报告“完成架构迁移但性能目标未通过”，不能换一个有利指标追认成功，也不能以Rust主进程小而忽略外置Chromium成本。

### 6.3 模型行为评估

固定一组实际任务：必须调用工具、无需工具、参数边界、目录搜索、工具结果失败、缺来源、敏感写操作、跨模态及多轮跟进。保持模型、参数、系统提示词来源和工具可用范围一致，每题重复取样，记录选择正确率、参数schema有效率、参数语义正确率、越权发生数、成本和完成情况。

schema通过不等于参数语义正确；回答“已写入”不等于文件生成；使用模型评分时保留人工可检查的事实断言。不可保证模型百分之百正确，硬性权限规则必须由执行层保证。

## 7. 证据写法与失败处理

每个场景记录：规格ID、任务ID、tested_sha、工作树摘要、依赖锁摘要、平台、时间、命令、原始退出码、预期、实际观察、日志/产物摘要、替身边界、PASS/FAIL/BLOCKED/NOT_RUN。

不得用日志行数、代码覆盖率、测试总数替代关键场景。超时要保留部分日志和进程清理结果；flaky必须记录重试次数与所有失败，不能只保留最后一次绿灯。真实秘密必须在写日志时脱敏；需要受限原始记录时保存在明确授权的位置，不随本仓库或任务书上传。

本包自带的`validate_bundle.py`只检查文档规格、映射、链接和校验和，不能执行或证明以上工程验收。

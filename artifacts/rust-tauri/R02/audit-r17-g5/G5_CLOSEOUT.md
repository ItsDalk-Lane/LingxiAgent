# R02 G5 进程与清理组：本轮交接

## 覆盖范围与改动

本组逐项检查 A01、A03、A04、A05、A07、A09、A11、A12、A13、A14，以及 A15 shell 的正常停止、异常 trap、服务/探针句柄、证据目录重用。十个由本组维护的脚本当前 SHA-256 见 `g5-source-sha256.txt`；A15 shell 的最终内容由根代理负责，本组只先加了 `A15_EVIDENCE_DIR` 环境变量及两次正常关停的有界检查，根代理随后继续修改。

- 正常关停复用已有四态归属检查和有界 TERM/KILL；必须在真实回收后立即清空句柄，关停退出码异常不能报绿。故意崩溃的入口仍先 KILL，并核退出码 137。A12 没有 READY 但仍活着的服务不再直接无限 `wait`。
- A11 开放 WS 的 Python 探针、A13 外部写锁进程、A14 风暴探针均限时回收并核真实退出码。A14 历史代码把 `PROBE_PID=$!` 写进 Python heredoc，真实运行暴露 `SyntaxError`，已移回 Shell heredoc 结束后的正确位置。
- 异常 trap 若仍有本轮活进程或归属不可观察，明确失败并保留合成 home 供核查，不在活进程下删数据根。A11 同时清理由本轮创建的备份、恢复与失败演练目录；正常完成明确返回 0，避免 EXIT trap 把成功误写成失败。
- 十个脚本在写入证据前拒绝非空或符号链接证据目录；A13 原已有非空拒绝，本轮补了符号链接拒绝。独立直跑不得覆盖旧日志。
- A01 新增四个 R00 serve 负面案例：一般启动失败无 READY；数据版本过新拒启、明确错误、不得切到备用数据根。原始 stdout/stderr、主/备用合成 home 前后目录内容摘要、原数据版本印章 SHA 均保留。主 home 中服务拒启时生成的诊断日志/锁文件按 R00 原句不算数据根切换。

## A16 同根因补查：证据目录重用

A16 原脚本用 `mkdir -p` 接受已有目录，随后 `tee -a` 与多处 `>` 会把复跑材料混在一起或覆盖首次失败日志。这是 R02 全范围内的原有证据链缺陷。现在脚本在任何写入前拒绝已存在或符号链接的 A16 证据根；只在全新根中创建 `legacy-entry`，每次运行必须使用新路径。未改 Git 基线、归因和门禁判定逻辑。修改文件为 `scripts/rust-tauri/r02_t08_legacy_entry_regression.sh`，小检查时 SHA-256 为 `7b7c4a4dd400d6fdfc672715e5c073ed85df93405e93cbdf05eef779b8ee3c68`。

本轮静态 `bash -n` 首次暴露脚本现存两处单引号注释会中断 Shell 内嵌 awk 文本，报在原第 658、1411 行。这两处分别位于 R9-F01 与 R10-F01 说明段，按源码位置推断是相应后续修复引入；未找到单独的原始运行日志可证明准确引入时点。仅将注释中的所有格写法改为无引号字样后，`bash -n` 与 `git diff --check` 均 exit 0。首次静态失败已如实记录在本轮对话的工具原始输出，不算运行通过。

定向小检查在 [`a16-evidence-guard-j4nc3a6j/result.json`](a16-evidence-guard-j4nc3a6j/result.json) 保留三次实际命令、UTC 起止、退出码及原始 stdout/stderr。已有目录与符号链接均 exit 1，旧日志前后 SHA-256 相同；全新目录可创建并写本轮摘要，随后因故意传入不存在的基线 SHA 在 E0 exit 1。这只证明目录保护与早期启动，**完整 A16 未执行**；最终候选必须在新证据目录合法重跑全量 A16，再看真实结论。

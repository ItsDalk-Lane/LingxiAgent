# LA-1B09760C2B1C 与进程清理生产者静态核查

R00 原始 `then`：`以前台服务进程运行，保留指定 channel 与数据降级约束`。原始第二断言：`启动/数据版本失败给错误，不偷偷切换数据目录`。`due` 要求在所列实施任务的阶段验收前完成并执行；实施任务同时列出 R02-T03 与 R07-T09。R02 负责真实服务进程、配置与实例边界；CLI 包装、channel、数据降级与终端诊断仍要有完整客户端证据。当前叶保持 `protocol_basis`，不能因 A01 部分证据而标为完整 PASS。

Rust 启动顺序为选择唯一数据根、规范化该根、取得同根独占锁、读取版本标记、建立认证状态、绑定端口。版本门禁的较新标记拒绝发生在认证与绑定之前；源码没有失败后尝试第二个根的分支。数据根优先级是显式 `--test-mode`、`--home`、`LINGXI_HOME`、`--config`；测试模式是明确要求新合成根，并在安全日志中说明忽略哪些低优先级来源。

A01 生产者现在分别记录以下入口：

| 入口 | 失败条件 | 独立证据 |
| --- | --- | --- |
| `--home` 高于备用 `LINGXI_HOME` | 较新版本标记 | `a01-newer-data.*.log`，原数据哈希、主/备用根清单，三项叶案例 |
| 仅 `LINGXI_HOME` | 较新版本标记 | `a01-newer-env-data.*.log`，原数据哈希、主/备用根清单，三项叶案例 |
| 仅 `--config` | 较新版本标记；显式清除环境变量 | `a01-newer-config-data.*.log`，原数据哈希、主/备用根清单，三项叶案例 |
| 显式 `--home` | 非法绑定地址 | `a01-invalid-bind.*.log`，主/备用根前后清单，非零/错误/无 READY 案例 |

每个版本拒绝案例都分别要求退出码 2、无 READY、明确版本阻止标记、原数据与版本标记哈希不变、备用根目录清单不变、两个根没有新运行数据库或本机令牌，并从原始 stderr 检查实际选中的根及来源。原 home 的诊断日志与锁文件允许出现，故不把整个原 home 前后清单相同作为通过条件。阶段图已钉住新增六项 env/config 案例。

客户端、管理、静态页及 CLI→Rust 生产者曾在超时或残留分支直接对保存的数字执行 `killpg(..., SIGKILL/TERM)`。当前四个生产者共用 `r02_owned_process_group.py`：只在对应 `Popen` 子进程未回收、进程组号与会话号都等于该 PID 时发信号；归属不能证明则不发信号并记录失败。已回收领袖的同号组即使探测到存在，也不再凭旧数字补发 KILL。CLIENT、management、static 三个证据目录必须全新，拒绝已存在目录与符号链接。

本轮只执行了不监听端口的静态检查。`static-checks.json` 保存了逐条命令、UTC、退出码、原始 stdout/stderr；8/8 为 exit 0。`candidate-sha256.json` 保存 A01、四个 Python 生产者、公共 helper 与阶段图的本轮摘要。尚未运行 A01 或任何真实服务生产者，相关行为验证仍为 **BLOCKED**。旧候选运行结果不能替代本候选验收。

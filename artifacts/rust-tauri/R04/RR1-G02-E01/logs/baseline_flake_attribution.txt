Root cause: the fast-exiting child (/usr/bin/env, /usr/bin/true, /bin/pwd — exit in ~1-2 ms)
is reaped by tokio's process-wide SIGCHLD handling (which may run on ANY runtime thread of
the test process) BEFORE spawn_oneshot's verify_group runs its getpgid. The baseline then
refuses a legitimately-ours child that had already fully run.

This is the spawn-side instance of F02's "OS reaping precedes the ownership state update"
family. The same root produced the earlier ask_session_exec_command_round_trips_the_approval_face
flake (/usr/bin/true refused -> run Failed -> journal not Succeeded at line 1485).

Fix (procsupervisor.rs verify_group): getpgid(pid) == -1 for a microseconds-old child of
ours means the child exited and was reaped; the record is ADMITTED (the reaper owns the real
Child and resolves the stored exit status; the child_reaped gate closes all group signalling
from the reap publish on). Refusal remains for a live pid reporting a DIFFERENT pgid.

After the fix: 20/20 full-suite runs green (logs/t05_stability_final.txt).

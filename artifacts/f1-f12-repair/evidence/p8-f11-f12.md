## 实现（F11）

- `core/media/media-parameters.ts`：新增 `resolveSpeechParameters({ input, providerDefaults })`
  ——语音域专用解析步骤。优先级固定：显式输入 > 语音供应商默认 > 协议默认（适配器收口）。
  语义显式化：undefined/null = 缺失（null 绝不进 Number()）；显式非法值透传协议层按既有
  白名单/边界处理；供应商默认只接受类型健全值；模型身份不参与（execution target 已解析
  的模型不可被默认改写）；只输出解析到值的字段。
- `core/media/universal-media-manager.ts` `_submitSpeechWithinTrace`：
  `getSpeechConfig().providerDefaults[target.providerId]`（逻辑 provider 身份，与设置页
  ProviderMediaDefaults 保存键一致；credentialProviderId 只用于凭证）→
  `resolveSpeechParameters` → 有效参数注入 params（TaskStore.params 与语义观测
  captureSemanticRequest 同源记录 voice/speed/format）。
- `core/media-adapters/speech.ts`：三条云端路径（openai-audio-speech / minimax-t2a-v2 /
  dashscope-qwen-tts）全部删除 `ctx.config?.get?.("providerDefaults")` 读取与
  `providerDefaults?.model` 模型回退；voice/format 白名单、speed 边界改用严格类型判定
  （typeof number + Number.isFinite；0 是合法显式值）。MiniMax 现在也尊重 manager 解析出的
  speed（旧实现忽略默认 speed）。系统 say 路径不变（本就不读配置，只收它支持的
  voice/speed）。

## 实现（F12）

- `core/media/task-store.ts`：
  - `completeSynchronousSpeechTask(taskId, { files, generatedDir })`：files 非空 + 每个条目
    resolve 后必须位于 generated 根目录内（拒绝 `..` 逃逸）+ 磁盘真实存在 →
    status='done'、submitState='completed'、completedAt 定格、failReason 清空；内存同步终态
    （update 直接改 Map），持久化沿用既有 debounce（不谎称同步 fsync）。幂等：已 done 重复
    完成返回 idempotent 且不改 completedAt；cancelled/failed/aborted 拒绝改 done。验证失败 →
    任务标 failed（failReason 具体）并返回 {ok:false}。
  - `recoverSynchronousSpeechTasks({ generatedDir, now })`：只处理
    `type='speech' && delivery.mode='response' && status='pending'`——文件全部存在 → done；
    缺失 → failed（"speech output file missing after restart"）。终态不改写；不重新合成、
    不通知会话、不产生新模型调用。图片/视频与 session 投递 pending 一律不动。
- `core/media/universal-media-manager.ts`：
  - response 投递：提交成功且 files 登记后、返回 response 之前调用
    `completeSynchronousSpeechTask`；不 ok 即抛错（调用方拿到明确失败，不存在
    ok=true+永久 pending）。不 poller.add、不 deferred:register、不 task:register、
    不发聊天语音消息、不触发父会话续跑（这些副作用本就只在 !responseDelivery 分支）。
  - session 投递：保持既有 deferred/task:register/poller 流（fake-async 检测让带文件的
    同步任务在轮询首跳即完成）。
  - `start()`：启动时执行 `recoverSynchronousSpeechTasks`（已有恢复位置收口）。

  且 `buildSpeechHelper` 无 run/read/rootDir 注入。

测试定型过程中的两处夹具修正（非弱化断言）：
- 假 helper 补 `#!/usr/bin/env node` shebang——真实 helper 是可执行 Mach-O，
  无 shebang 的文本文件本来就 spawn 不了，无 shebang 时连正确实现也无法通过。
- A11 big-stdout 假 helper 改为 write 回调里再 exit——`process.exit` 会截断
  尚在冲刷的 8MB 写入，截断后永远到不了 4MB 上限，测试的是假进程自己。
- A08/A10 取消驱动从固定 80ms sleep 改为等 pid 落盘（`waitForPidFile`）——
  node 启动方差会打中尚未执行脚本入口的进程，属同步化修正不是 sleep 绕过。

## 实现清单

### F4 宿主授权（A01–A05、A15、A01b）

- 新增 `desktop/speech-permissions.cjs`：`createSpeechPermissionController({platform, loadNativeBridge})`
  + 生产单例 `getSharedSpeechPermissionController()`。
  - 只读查询绝不触发授权请求（A01）；
  - raw 0/1/2/3 → not_determined/denied/restricted/authorized，未知 raw → bridge_unavailable；
  - 单飞：并发 requestAuthorization 合并为一个在途原生请求（A03）；
  - 已终结状态（denied/restricted/authorized）直接回包，不再调用原生层（A04）；
  - dispose 在途按 bridge_unavailable 结算一次，晚到原生回调丢弃（A05）；
  - 非 macOS 返回 unsupported 且不加载桥（A15）；桥缺失 → bridge_unavailable 不崩不弹窗（A01b）。
- 新增 `desktop/native/LingxiSpeechPermissions/`（`speech_permissions.mm` + `binding.gyp`）：
  Node-API（C 接口）桥，导出 getAuthorizationStatus / requestAuthorization / dispose；
  授权回调经 TSFN 跨线程投递，CallJs 一次性 release；dispose 用 abort 模式丢弃排队投递。
  单例默认加载路径：LINGXI_SPEECH_PERMISSIONS_BRIDGE override → 打包 Resources/speech/macos/
  （app.isPackaged + process.resourcesPath）→ dev 的 dist-speech/mac-<arch>/。
- 新增 `scripts/build-speech-permissions.mjs`：node-gyp rebuild `--target=<electron 版本>`
  `--dist-url=https://electronjs.org/headers`（硬合同：Electron 头），产物复制到
  dist-speech/mac-<arch>/lingxi-speech-permissions.node；node-gyp 12.4.0 补进 devDependencies
  （此前只是传递依赖，lockfile 已同步）。
- `desktop/main.cjs`：IPC `speech-permission-status`（只读）/ `speech-permission-request`
  （渲染层用户手势触发），两者 wrapIpcHandler + `BrowserWindow.fromWebContents` 校验；
  will-quit 里 dispose 共享控制器。
- `desktop/preload.cjs` 暴露 `window.hana.speechPermissionStatus/Request`；
  `desktop/src/react/types.ts` PlatformApi 增补两方法与 `SpeechPermissionState` 联合类型。
- `desktop/src/react/components/InputArea.tsx`：听写模式录音前先查 Speech 授权
  （status → not_determined 才 request），非 authorized 显示
  `input.dictateSpeechPermissionBlocked` 引导文案（五语言）并中止录音（P4.2）。

### F5 Swift helper 异步化

- `desktop/native/LingxiSpeechHelper/Package.swift` 拆三 target：库 LingxiSpeechCore +
  薄壳 executable + 断言式测试运行器（本机 CLT 无 XCTest/swift-testing 模块，
  `swift run lingxi-speech-core-tests`，失败退出码 1）。
- `Sources/LingxiSpeechCore/RecognitionCoordinator.swift`：单次结算协调器
  （created→running→succeeded/failed/timedOut/cancelled，首个终局获胜，
  continuation 恰好 resume 一次；超时/取消走 `task.cancel()`，绝无 `finish()`）；
  `attachTask` 与终局的竞态在锁内判定、终局后挂上的任务立即取消。
- `Sources/LingxiSpeechCore/SpeechTranscriber.swift`：`async transcribe()`，
  CheckedContinuation + TaskGroup 竞速超时；识别回调落独立 OperationQueue
  （`recognizer.queue`，maxConcurrent 1）；recognizer/request 非 Sendable，
  在任务闭包内创建不跨任务捕获（Swift 6 sending 约束）。信号量/轮询全删。
- `Sources/LingxiSpeechCore/HelperOutput.swift`：stdout 单行 JSON protocol 2
  （`{ok, protocol:2, text?, resultCode?, code?, message?}`）；空结果显式 EMPTY_RESULT；
  失败 stdout 结构化 + stderr 人类可读 + exit 2。
- 保留 F4 边界：helper 只读 `authorizationStatus()`，绝不 requestAuthorization（裸进程会 SIGABRT）。

### F6 Node 适配器异步生命周期 + P4.6 路径合同

- `core/speech-recognition/system-speech-adapter.ts` 重写：
  - `SYSTEM_SPEECH_ERROR_CODES` 九码（HELPER_NOT_FOUND/PERMISSION_REQUIRED/
    PERMISSION_DENIED/RESTRICTED/RECOGNIZER_UNAVAILABLE/TIMEOUT/CANCELLED/
    INVALID_OUTPUT/PROCESS_FAILED），错误带 `.code`（SystemSpeechError）；
  - `resolveSystemSpeechHelperPath({env, cwd, arch, hanaRoot})`：override（校验存在性）
    → 打包（IS_PACKAGED=1 时 RESOURCES_PATH 形状校验 → APP_PATH/EXEC_PATH 推导；
    缺失即 HELPER_NOT_FOUND 安装损坏，不回退 dev 残留）→ 仅 dev 的
    dist-speech/mac-<arch>；绝不从 server 进程的 process.execPath 推导；
  - `transcribe(input, {env, platform})`：异步 spawn（无 shell），4MB stdout 上限，
    结构化 protocol-2 行即时结算 + close 兜底解析 + 旧式 stderr 兼容映射；
    单次结算：错误终局先有界终止同一子进程（SIGTERM → LINGXI_SPEECH_KILL_GRACE_MS
    宽限 → SIGKILL）确认退出后再 reject；结果终局立即 resolve 并后台回收；
    LINGXI_SPEECH_PROCESS_TIMEOUT_MS（默认 150s）进程上限 + --timeout 120s 识别上限；
    AbortSignal 贯穿（取消绝不记为成功）；观测层 noteProviderWireUnavailable 保留。
- `server/routes/media.ts`：POST /media/asr/transcribe 透传 `c.req.raw.signal`；
  `core/speech-recognition-service.ts`：payload.signal → _transcribeWithAccounting →
  adapter.transcribe({signal})（voice-attachment 后台路径不带 signal，行为不变）。
- `scripts/build-speech-helper.mjs`：run/read/rootDir 依赖注入（行为不变）。
- `package.json`：pack/dist 在 electron-builder 前接 build:speech-helper +
  build:speech-permissions；build.mac.extraResources 已有 dist-speech/mac-${arch}/ →
  speech/macos/ 映射（本次核实）。
- `.github/workflows/build.yml`：macOS job 在 electron-builder 直调前新增
  "Build speech helper and permissions bridge"（CI 不经 pack/dist 脚本，须单独接线）。
- `scripts/resign-adhoc.cjs`：ad-hoc 重签链补签 lingxi-speech-permissions.node
  （1c），保持 `--deep --strict` 校验可过。

  事件丢弃」「attachTask 竞态」）。
- 真实编译实测（本机 arm64，非 mock）：
  - `npm run build:speech-permissions`：node-gyp 对 Electron 42.8.1 头编译通过，
    `file` = Mach-O 64-bit bundle arm64；plain node 加载成功，三导出可枚举，

    protocol-2 JSON；合成 0.5s 正弦 WAV 跑 transcribe → 结构化
    `{"ok":false,"protocol":2,"code":"PERMISSION_REQUIRED",...}` + exit 2
    （真机 fail-closed，不弹窗不崩）。

- 回归：既有 speech/media 十文件 73/73；media-route 测试按 F6 新合同更新
  （signal 注入以 `expect.any(AbortSignal)` 断言）。

- `npm run typecheck`：tsc ×3 全绿。
- 门禁：persistence fingerprint 已按 compatible 重锚（理由：signal 透传无 schema

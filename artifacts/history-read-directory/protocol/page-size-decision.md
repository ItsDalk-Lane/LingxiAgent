# 页大小决策（E06.2）

- 决策：**推荐页大小 K = 100**（`server/history-read/protocol.ts` HISTORY_PROTOCOL_PAGE_LIMIT，单一配置点；省略 limit 的旧请求仍由服务端默认 50 承接；显式上限 200 不变）。
- 依据：`protocol/page-size-experiments/summary-e.json`（命令：`node scripts/benchmark-history-protocol.mjs --phase E --sizes 1000,10000 --seed 20260910 --page-sizes 50,100,150,200 --rtt-ms 0,50,150 --bandwidth-mbps 10,50`，exit 0，语义失败 0）＋ D 基线锚点 `protocol/baseline-d/`。
- 环境：同 seed 20260910/同夹具/同外部状态；每候选从初始副本重建；7 链路格（loopback + rtt0/50/150 × bw10/50）。

## 三、候选淘汰理由

- **K=50**：基线（对照）。往返 201 次、最劣全翻 31.8s——无放大必要，但保留为旧客户端兼容默认。
- **K=150**：全翻 12.3s（较 K=100 +6.2s 改善仅 −24%），首屏 p95 升至 179–184ms（较 K=100 +22ms），每页正文 89KiB。边际收益不抵首屏与载荷增幅 → 淘汰。
- **K=200**：全翻 10.7s（较 K=100 再 −34%），但首屏 p95 209.9–210.8ms 逼近限额 220.4ms（裕量 <5%），每页正文 116.9KiB 为 K=100 的 2 倍 → 淘汰。
- **K=100**：往返与全翻主要收益（−50% 请求、−49% 全翻时）在最小增幅页上取得；首屏 p95 与 K=50 持平（+1.9~3.7ms）；单页处理/内存增量可忽略 → **选定**。

## 四、落地（E06.3）

- 单一配置点：`server/history-read/protocol.ts` HISTORY_PROTOCOL_PAGE_LIMIT = 100；消息路由头 `Lingxi-History-Page-Limit` 与概览 `pagination.recommendedLimit` 同源读取（一致有测试）。
- 省略 limit 的旧请求：服务端默认 50 不变；显式 limit 规则与上限 200 不变；all/reconciliation 的 limit 策略不变。
- 新客户端：能力未知首请求省略 limit（=50）；确认 `Lingxi-History-Protocol: 1` 且推荐值 ∈ {50,100,150,200} 后，后续新页显式携带 K；能力绑连接/认证 epoch；头建议与概览建议冲突 → 保守 50 + 诊断。
- 校验记录按 effective limit 入键（50 页标签不串 100 请求）。
